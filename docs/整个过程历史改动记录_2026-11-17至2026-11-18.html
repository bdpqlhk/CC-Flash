CC Flash · 整个过程历史改动记录

当前最新：v1.2.6（2026-11-22 全量复审修复） · 时段：2026-11-17 至 2026-11-18 · 版本：v1.2.3 · 与《技术实现文档》《需求设计文档》《后期规划》配套阅读
本段主题消息工作台落地、共享剪贴板双向同步、浏览器回原聊天室、桌面布局收敛，以及一轮全端深度检查后的 10 项修复。

一、消息工作台：设备发现并入发送页

  • 桌面端：「消息发送」页左侧新增 200px Snapdrop 风格周边设备栏（本机身份卡 + 扫描雷达 + 附近设备列表，在线 / 忙碌 / 最近活跃）；点设备即选中发送目标，输入栏切换为「直发」，时间线追加本机回执；点本机共享或「×」取消目标。
  • 设备栏底部不放二维码 / 复制地址：顶栏、服务中心、二维码弹窗已覆盖，移除重复入口，减少视觉与操作负担。
  • 手机 App：底部收为「发送 / 设置」两标签；发送页顶部为目标横条，点「全部设备」展开设备面板；选中后同样直发并显示回执。
  • 浏览器：电脑 / 手机浏览器保持原聊天室单页，不再渲染底部标签、不做设备发现、不提供设置页；setView 把 discover / settings 映射回 transfer。
  • 直发链路：文本走对方 /api/chat，文件走对方 /api/upload；目标开启访问令牌时按端点记忆配对码；内容进入对方公共聊天与共享目录。

二、共享剪贴板：双向、无开关

  • 新增 GET / POST / DELETE /api/clipboard，共享槽上限 20,000 字并持久化；clipboard:changed 走 WS 事件总线。
  • 桌面 / 手机 App 在页面可见时每 1.5s 比对本机剪贴板，变化即发布；收到事件立即拉取并 writeText，另有 4.5s HTTP 兜底；clipSyncBusy 期间的远端值进 pendingRemoteApply，忙完再应用。
  • 输入栏底部「＋」面板中的剪贴板入口合并为唯一「粘贴」：本机剪贴板优先；浏览器读不到时直接回填共享槽文本，不弹面板；输入框粘贴事件把文本自动回传电脑。
  • 默认关闭，可在 CC设置 开启，不建独立模块；页面不可见时不同步，重新可见时重置 lastSentClip 并补一次远端应用；远端内容应用后 toast「已从 X 同步剪贴板」。
  • 浏览器受安全上下文限制时复制失败回退 execCommand；共享内容同一 Wi-Fi 可见，公共网络建议开启访问令牌。

三、桌面布局与响应式

  • 侧栏宽度 176px；设备栏 200px；共享文件抽屉 320–380px（字号加大、分页占满底栏）。
  • 981–1180px 宽度下文件抽屉改为带遮罩的覆盖层，避免挤压聊天区；≤980px 进入窄屏布局；390 / 320 宽度无横向溢出。
  • 手机 App 使用目标横条 + 设备面板；桌面浏览器、手机浏览器保留原聊天室顶部 / 单列布局。
  • 设备栏改为 Snapdrop 风格：本机身份卡（昵称 + 在线点）、扫描雷达（最多 6 个设备点 + 旋转扫描）、附近设备列表（在线 / 忙碌 / 最近活跃 + 收藏）；雷达中心与身份卡按当前终端显示手机 / 电脑图标；手机设备面板复用同一套身份卡与雷达。在线绿点、状态徽标绿点均有呼吸动效（尊重 prefers-reduced-motion）。

七、构建产物瘦身与 Release 精简

  • 前端：删除已废弃的 discover 页面模板与 .disc-* 样式、旧 peer-send / LocalSend 面板残留样式与函数；主包 274.25 → 288.79 KB（gzip 115.39 KB），CSS 99.78 → 94.82 KB（gzip 17.60 KB）。

八、交互收口

  • 粘贴不再弹框：输入栏「粘贴」先读本机剪贴板；读不到时直接把共享槽文本回填输入框，无任何中间面板。浏览器输入框的 paste 事件会把文本写回共享槽，电脑端随后自动写入系统剪贴板。
  • 呼吸绿点：手机端「实时」单绿点、设备身份卡在线点、设备列表在线点统一呼吸动画；离线/忙碌保持静态。
  • 周边设备：桌面 200px 设备栏与手机设备面板采用身份卡 + 雷达 + 列表；雷达点位置固定，避免刷新时乱跳。

九、HTTP / WS 接口健壮性巡检

  • 文件列表符号链接：先看 file_type 再 metadata，跳过指向目录/文件的符号链接，避免递归到共享目录之外或形成环；非普通文件（FIFO/设备节点）也不进列表。
  • 上传声明大小：客户端多送字节时立即 413 并清理半截文件，不再先写超量数据再在结束时拒绝，防止谎报小 size 绕过磁盘预检。
  • JSON 体积上限：聊天 256KB、剪贴板 128KB、分享票据 / hello 16KB；超过直接 413，避免 2MB 默认上限的内存分配。
  • WS 慢客户端：所有 send（心跳/事件/同步提示/Pong）加 5s 超时，半开或只连不读的连接不会长期占用 64 个 WS 许可。
  • 前端请求：GET 统一 cache:"no-store"；设备列表用递增序号丢弃迟到响应；状态/聊天请求的 10s 中止链路保留到 body 读取完成；手动刷新失败给出提示。
  • 验证：新增符号链接单测；上传超量、聊天/剪贴板超限均实测 413；两轮全端 UI 与 API 回归通过；cargo test 20 项通过。

十、设备发现增强（快 / 准 / IPv6）

  • 主动探测：新增 POST /api/discovery/probe；启动、手动刷新、WS 重连时发 probe，收到 probe 的设备立即单播回宣告（500ms/来源限流），不再等下一次 3s 周期。手动“重新扫描”现在真的会发 UDP 包，等待约 200ms 再拉设备表。
  • 更快：启动即宣告 + 立即 probe；前端设备轮询 12s → 3s；新增/忙碌/昵称/端口变化都广播 devices:changed，WS 在线时立即刷新。
  • 更准：正常停止发 bye，对端同 IP 同 id 才移除；TTL 120s → 15s，异常离线最多约 18s 从列表消失；15s 内保留“最近活跃”提示。
  • IPv6：新增 [::]:53318-53321 v6only 监听、IPv6 link-local 多播组 ff02::ccf1、逐网卡 interface index 出口、v6 单播回包；link-local 设备地址带 %en0 zone，前端 URL 编码为 %25en0。HTTP/WS 继续走双栈 [::]。
  • 端口顺延：发现端口从固定 53318 扩展为 53318-53321；实例绑定首个空闲端口，发送端向整个范围宣告，packet 携带 dport，回包按 dport 返回，因此端口冲突/同机多实例仍可互相发现。
  • 单播兜底：缓存最近 32 个设备 IP；多播被企业/路由器过滤时，启动/手动刷新/每 30s 向历史地址发单播 probe，兼容端口顺延；空设备状态按 macOS / Windows 显示本地网络 / 防火墙指引，并提供「网络设置」按钮。
  • 抗噪：probe 每来源 30 次/分钟；发现报文单来源 50 包/秒；仍只接受私网/链路本地来源、端口 1024–65535、id 长度与自 id 校验；对慢 WS 发送已有 5s 超时。
  • 验证：本机用 en12 link-local 发送 IPv6 多播 announce/bye，`/api/devices` 正确出现/移除带 %en12 的设备；v4 announce/bye、状态变化 WS、probe 接口均通过；20 项 Rust 测试通过。
