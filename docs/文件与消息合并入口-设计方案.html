01
DECISION

一个入口，两种节奏。

不是把两个页面硬塞进一个标签，而是让它们同时在场：宽屏一眼看到文件和对话， 窄屏只做一次切换。文件仍是文件列表，消息仍是聊天，用户不需要学习第二种心智模型。

DESKTOP / ≥980px

对话 + 文件抽屉

主区是一条对话时间线（文字气泡、文件卡片、文件组混排），右侧共享文件抽屉负责长期管理；抽屉宽 clamp(340px,30vw,400px)，可收起。边传边聊，上传进度不打断输入。

桌面壳顶栏：左标题/副标题，右运行状态 + 地址 + 复制/二维码/浏览器按钮
MOBILE / <980px

一条对话 + 底部面板

没有分段控件：聊天时间线就是主屏。顶部共享文件按钮打开底部面板（86dvh），未读只挂在「消息发送」入口，新文件在文件按钮上点绿点。

去掉旧的聊天悬浮球与分段入口，入口不再重复
NAVIGATION

只留一个「消息发送」

真实桌面侧栏 3 项：消息发送 / 服务中心 / CC设置；移动壳不显示侧栏，设置入口在房间头「⋯」。未读徽标从「文本消息」移到「消息发送」。

介绍页「立即开始传输」也落到这一页
02
PRINCIPLES

简单，不等于少做。

这次合并只改变「在哪里」，不改变「怎么做」。下面四条是取舍时的尺子。

01 / NO NEW MODEL

不制造第二种心智模型

文件仍然是文件列表，消息仍然是对话。合并不是改成时间线，也不是把聊天塞进文件行。

02 / GLANCEABLE

宽屏一眼看到两件事

传文件时能看到对方刚发的消息；聊天时能看到上传是否完成。共享文件抽屉可随时收起，把宽度还给时间线。

03 / ONE CHOICE

窄屏只做一次选择

一条对话就是主屏，文件管理通过底部面板打开；打开 / 关闭面板不重建时间线，不丢滚动与草稿。

04 / ZERO REGRESSION

旧功能原地可达

上传方式、进度、取消、改名提示、排序分页、批量删除、分享、聊天 Markdown、未读、清空全部保留；新增应用内预览与五套配色。

03
DESKTOP

桌面：从双栏到「对话 + 文件抽屉」。

当前实现（v1.2.2）在宽度 ≥980px 时，主区是一条完整的对话时间线，右侧是共享文件抽屉： 时间线可以有消息、文件卡片、文件组与在途上传；抽屉负责排序、分页、批量删除与分享。 两区各自滚动，页面本身不滚；没有可拖动接缝，抽屉宽度为 clamp(340px,30vw,400px)，点顶部文件夹按钮收起 / 展开。

顶栏（真实桌面）：标题 / 副标题在左；运行状态 + 地址 + 复制 / 二维码 / 在浏览器打开按钮整组靠右上； 地址宽度按内容自适应（ch 计算），窄于 900px 时整组换行并撑满。 房间头在桌面壳压成一条 50px 轻量工具条。

04
MOBILE

移动：从分段到「一条对话 + 底部面板」。

窄屏不硬塞双栏，也不再用「文件 / 消息」分段。聊天时间线就是主屏：上翻看历史、下拉贴底、输入栏吸底； 共享文件通过房间头的文件夹按钮打开底部面板（高 86dvh），点把手 / 「完成」关闭。 原来的聊天悬浮球退场，避免出现第二个入口；面板开关不重建时间线，不丢滚动和草稿。

字号按触屏整体上调：消息 15px、文件文件名 13px、元信息 11px；输入框 16px 以避免 iOS 聚焦缩放。

05
INTERACTIONS

合并之后，这几件事必须仍然正确。

入口合并最容易出问题的地方不是布局，而是未读、拖拽、状态保持和服务状态提示。下面逐条定义。

未读怎么算

FOREGROUND
消息发送页在前台
且窗口有焦点

对话时间线可见时立即已读；滚回底部也会立即追平未读。

立即清零
BLURRED
消息发送页在前台
但窗口失焦

未读保留；回到窗口并聚焦后清零。文件绿点同理。

保留
ELSEWHERE
在服务中心 / 设置
或文件面板打开时

侧栏「消息发送」显示未读；浏览器标签标题同步数字。

显示角标

聊天上翻时，底部浮出「N 条新消息 · 回到底部」；点击回底并清零。避免用户看不到新消息，也避免强行拽回底部。

拖拽即上传

文件拖到页面任意位置都进入上传态：整页浮出带主题色的投放层「松手传到电脑」。

  • 落在对话区或文件抽屉 / 面板都归到文件，不产生“聊天收文件”的歧义。
  • 拖入文件夹保持目录结构；离开页面即取消。
  • 页面级 dragover/drop preventDefault，不会触发浏览器导航。
松手传到电脑3 个文件 · 保持目录结构

上传不打断聊天

时间线与文件面板独立：上传进度只更新文件卡片 / 总览条，聊天输入框不被抢焦点；上传完成只刷新文件列表，不滚动或重排消息。

  • 客户端并发闸 3 个、无进展 125s 回收保持不变；服务端另有上传 16 / 下载 32 并发闸，超限 429。
  • 同名自动改名提示仍出现在上传条目上。

开关面板不丢状态

移动端时间线常驻，共享文件面板只是覆盖层。文件分页、勾选、排序，聊天滚动位置、未读水位、输入草稿全部保留。

桌面 / 浏览器端时间线也始终挂载；切到服务中心再回来，列表与聊天不重新拉取（WS 事件照常增量更新）。

服务状态只有一处

服务停止时，合并页顶部只出现一条内联提示「服务未启动 · 去启动」，上传区禁用；不再两个页面各提示一次。失联仍走整页「无信号」。

移动壳失联页在 v1.2.2 改为「重新启动本机服务」（连电脑模式可回到本机节点，也可到 CC设置改地址）。

预览、Markdown 与主题

浏览器与移动端：图片 / PDF / 纯文本（txt / md / log / csv）/ 音视频打开应用内全屏层，右上角「关闭」或 Esc 返回；缩略图、预览按钮、行尾菜单都可进入。文本超过 2MB 先提示下载，Office 文档、压缩包等浏览器无法渲染的类型走下载；html / svg / xml 不以网页形式内联，避免同源脚本。真实桌面沿用系统程序打开文件，PDF 与移动壳同样交系统浏览器（WebView 无 PDF 渲染器）。

聊天支持 Markdown：标题、无序 / 有序列表、引用、围栏代码块、行内代码、链接、粗体 / 斜体 / 删除线；输入框为多行 textarea，随内容长高（最高 160px）。

外观为 5 套低饱和配色（深空蓝 / 石墨玫瑰 / 森林薄荷 / 暗夜紫 / 墨色琥珀）× 亮色 / 暗色 / 跟随系统；桌面壳对话气泡跟随主题变量，浏览器与移动端气泡保持浅底黑字以保证可读性。

键盘与可达性：F5 刷新文件、Ctrl/Cmd+V 粘贴上传；桌面 Enter 发送、Shift+Enter 换行，纯触屏 Enter 换行、按钮发送；Tab 顺序为 输入栏 → 时间线 → 文件抽屉。触屏无 hover 时文件动作常显，尊重 prefers-reduced-motion。

主区为单列时间线：聊天消息、远端文件、本机上传文件 / 文件组按时间排序；文件卡片四态就地更新。

3共享文件抽屉 / 面板

桌面 clamp(340px,30vw,400px) 右侧抽屉，可收起；<980px 切换为 86dvh 底部面板；复用现有排序、分页、选中与批量删除。

4未读与状态

未读按消息 id 计算；页面可见且窗口聚焦时追平，滚到底会触发同一判定。服务停止只在合并页提示一次；新文件用 fileDot 绿点。

5预览与外观

浏览器 / 移动端使用应用内全屏预览层（图片 / PDF / 文本 / 音视频），真实桌面走系统程序，Office / 压缩包下载；5 套配色 × 亮 / 暗 / 跟随系统，桌面气泡跟随主题。

6回归验收

按第 09 节矩阵跑桌面宽/窄、网页宽/手机、上传中聊天、拖拽落面板、停服、失联、配对与票据。

改动风险与规避
  • 时间线里文件与消息混排，批量上传必须合并为文件组，否则一次 200 个文件会淹没聊天记录。
  • 移动端图省事用固定高度会把输入栏顶出屏幕；统一走 dvh / visualViewport 与安全区，键盘弹起时收起 ＋ 面板。
  • 未读清零条件曾分散在 setView / loadChat / openChat，合并后统一到 markChatSeen()，防止重复计数或漏清零。
  • 音视频 / PDF 会发多次 Range 请求，不能使用一次性分享票据（首个 206 即销票）；应用内预览改用长期 PIN 直连，且不写进浏览器历史。
  • html / svg / xml 若以 inline 打开会运行在服务同源上，服务端 is_inline_safe 必须继续排除这些类型。
08
TRADE-OFFS

为什么最终是对话时间线，而不是标签页或双栏。

四个方案都做过桌面推演。最终落地的是「一条时间线 + 共享文件抽屉」：既借用微信的熟悉感，又保住文件管理能力。

方案优点代价结论
纯标签页 实现最省，入口确实合并了。 宽屏仍要来回切换；传大文件时看不到消息，与现状差别不大。 不采用
统一时间线 + 文件抽屉 文件即消息，上下文完整；共享文件抽屉保留排序 / 分页 / 全选 / 批量删除，学习成本接近微信。 需要新增时间线模型与文件卡片，批量上传必须合并为文件组。 已落地
双栏 + 窄屏分段 宽屏文件与消息同时在场，窄屏一次选择；文件列表常驻。 需要可拖动接缝与两套移动分段状态；与最终采用的对话时间线不一致。 未采用
悬浮聊天抽屉 文件区最大化。 聊天被隐藏，入口仍然分裂；手机端已有过悬浮球，体验重复。 不采用
09
ACCEPTANCE

做到这些，才算“合好了”。

每条都可手动验证，不依赖主观感受。

✓侧栏只剩「消息发送 / 服务中心 / CC设置」三项，未读徽标只出现在「消息发送」。
✓桌面壳顶栏标题/副标题在左，运行状态+地址+复制/二维码/浏览器按钮整组靠右上；窄于 900px 整组换行撑满。
✓地址宽度按内容自适应（ch），不长不短；服务停止时显示「服务未启动」。
