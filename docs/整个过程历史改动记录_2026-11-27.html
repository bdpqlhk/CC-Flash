P2（已修复的主要项）

#问题修复
1服务端聊天 id 回退（历史文件丢失/崩溃丢尾部）时已读水位不重置，未读角标永久失效。loadChat 检测末条 id < seenChatId 时清零并同步 fresh 基线。
2Esc 关闭链缺 8 个弹层（确认框/更新/自启说明/设备配对/历史/文件菜单/局域网询问/复制兜底）；chatCovered 漏 confirm/showUpdate/autostartTip（确认框打开时收到消息会误清未读）。两集合按 z 序补全对齐。
3WS 重连 loadSharedClip() 不 applyRemoteClipboard()：断线期间对端剪贴板变化要等 4.5s 兜底。onopen 路径补 apply，与 sync:needed 对齐。
4/api/hello 前端发 platform/busy、后端 HelloIn 只收 nickname（serde 静默丢弃）——契约漂移。前端只发 nickname，注释说明 busy/platform 由 UDP 宣告上报。
5取消上传只 abort XHR：abort 时服务端可能已落盘，UI 显示"已取消"但文件在共享目录。取消后查 upload_status 幂等账本，已完成则转 done 并提示，否则再移除。

7peerBase 端口缺失回落本机端口：残缺宣告会把"发给对端"的请求打到自己。只认宣告值（0-65535），非法产出 port 0 URL 走网络错误；服务端宣告入口本就挡 0/超界。
8/api/clipboard、/api/upload_status 不在 NOISY_GET_PATHS：剪贴板 4.5s 轮询挤占 2000 条日志环。两路径入清单。

三、裁决为不修 / 维持现状（含理由）

项结论与理由
上传同名改名循环在 file_op_lock 内做慢盘 IO影响有界（hint 起点 + 4096 缓存 + spawn_blocking，上限 1 万次 stat，仅撞名路径触发）；把占位/标记/在途登记挪出临界区会重新打开"并发 DELETE 假成功"窗口，重构风险大于收益，维持现状。
媒体会话令牌不绑文件（同 IP 10 分钟可读全部共享文件）有意设计（缩略图/预览免逐文件开票），README 已如实描述；是否收紧为绑文件名留产品拍板。
桌面 open_lan 仅回环分支成死代码"桌面始终开放局域网"是已发布的产品决策（README 明文），仅存历史兼容命令；不改行为。
失联清空不清 fileEvents/uploads/directReceipts对抗复核：失联遮罩 z-index:1002 不透明全盖；fileEvents 恢复后由 loadChat 重建；uploads/directReceipts 属本机历史，网络抖动时清掉反而毁用户记录。维持现状。
Intro FAQ 900px 裁切 / 诊断包 pet-dbg 泄敏 / iOS 缺本地网络键三条均裁决不成立（内容实测 ≈160px；pet-dbg 仅窗口几何+白名单；iOS 未出包且四处文档如实披露）。
style.css 152 行成对重复注释批量去重高噪声大 diff、零功能收益，按最小 diff 原则不动；两处吞规则残骸（真正误导项）已清。
