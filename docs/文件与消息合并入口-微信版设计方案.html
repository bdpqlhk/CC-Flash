01
DECISION

对话即传输。

不再把「文件」和「消息」当成两个页面：上传的文件直接成为对话里的文件卡片，文字仍是文字气泡。 文件管理不消失，而是收进一个随时可打开的共享文件抽屉（桌面 340–400px / 移动 86dvh 底部面板）。 这样既保留微信式的熟悉感，也不牺牲批量管理能力。当前 v1.2.2 已按此结构落地，导航名称为「消息发送」。

TIMELINE

文件即消息

上传开始就在时间线里出现文件卡片：等待中 / 上传中 / 完成 / 失败都能看见，进度与取消就在卡片上。

批量上传自动合并为「文件组」，避免刷屏
FILE MANAGER

共享文件收进抽屉

完整文件列表、排序、分页、全选、批量删除、预览 / 打开 / 复制 / 下载 / 分享，全部在右侧抽屉或底部面板里；分页占满底栏。

桌面 340–400px / 移动 86dvh；新文件显示绿点
INPUT BAR

微信式输入栏

左侧「＋」打开上传面板（文件 / 文件夹 / 粘贴 / 共享文件），中间是多行 textarea（随内容长高，最高 160px），右侧发送。

桌面回车发送 / Shift+回车换行；触屏回车换行、按钮发送；全局粘贴与拖拽保留
02
WHY WECHAT

用户已经会用微信发文件。

这次合并最大的收益不是“少一个菜单”，而是借用一套已经被数亿人学会的操作习惯：在对话里发文件。

FAMILIAR

零学习成本

左右气泡、文件卡片、输入栏、＋面板——用户不需要理解“文件页”和“聊天页”的区别。

ONE-HAND

手机上更顺手

一条时间线向下滚，上传和聊天都在同一屏；不用在标签、悬浮球、底部面板之间切换。

CONTEXT

文件带着上下文

“为什么发这个文件”就写在它上一条消息里。文件卡片和时间线一起保留了传输的来龙去脉。

EXTENSIBLE

以后都加消息类型

预览卡片、文件夹、分享票据，都可以作为新的消息类型加入时间线，而不是再造一个页面。

03
DESKTOP

桌面：左边对话，右边文件。

主区是一条完整的会话时间线，右侧是「共享文件」抽屉（clamp(340px,30vw,400px)）。 抽屉默认打开，点顶部文件夹按钮可收起；它是布局内的一列，不做覆盖式浮层，宽度在 340–400px 之间随窗口变化，低于 980px 切换为底部面板。 真实桌面顶栏左侧是标题 / 副标题，右侧把运行状态 + 地址 + 复制 / 二维码 / 在浏览器打开按钮整组靠右上； 地址宽度按内容自适应，窄于 900px 时整组换行撑满。点一下文件夹按钮就能看到整个抽屉的效果。

HISTORY

只把本次会话的上传当消息

不伪造历史文件的发送者与时间。刷新后，历史文件回到共享文件抽屉；时间线只保留本次会话真实发生的上传与聊天。

ACTIONS

卡片与抽屉同一套动作

预览、打开、复制、下载、删除、分享在所有位置一致；移动端用「⋯」打开动作面板，避免长按与文本选择冲突。

浏览器 / 移动端：图片 / PDF / 纯文本（txt / md / log / csv）/ 音视频打开应用内全屏层，右上角「关闭」或 Esc 返回；Office 文档与压缩包下载；html / svg / xml 不内联。文本超过 2MB 提示下载；真实桌面沿用系统程序打开；PDF 在桌面 / 移动壳交系统浏览器。

06
FILE DRAWER

把文件管理收进抽屉，而不是删掉。

「文件即消息」解决的是发送与上下文；共享文件抽屉负责长期管理。两者共享同一份文件数据，动作与状态完全一致。

DESKTOP DRAWER

右侧抽屉

默认展开 clamp(340px,30vw,400px)，可一键收起；它是布局内一列，不覆盖时间线。排序、分页、全选、批量删除与现在完全一致，分页占满底栏。

顶部文件夹按钮显示总数，新文件出现绿点；浏览器 / 移动端缩略图、预览按钮、行尾菜单均可预览，真实桌面走系统程序
MOBILE SHEET

底部全屏面板

从房间头文件夹或＋面板打开，高 86dvh；点顶部把手或「完成」关闭，返回聊天。同样支持排序、分页、批量删除。

行尾「⋯」打开动作面板：预览 / 下载 / 分享 / 删除
SYNC

同一份数据

上传完成、删除、改名都会同时更新时间线与抽屉；文本消息按 id 计未读，新文件只点绿点。不会出现“对话里有、列表里没有”的分裂状态。

文件事件以 WS 推送为主、轮询兜底
07
INTERACTIONS

把微信的习惯搬过来，还要保证正确。

未读、拖拽、粘贴、键盘、空状态、服务停止——这些细节决定它是“像微信”还是“真的顺手”。

未读怎么算

FOREGROUND
消息发送页在前台且窗口有焦点

时间线可见，消息与文件卡片立即视为已读；滚回底部也立即追平。

立即清零
BLURRED
消息发送页在前台但窗口失焦

未读保留；回到窗口并聚焦后清零。

保留
ELSEWHERE
在服务中心 / 设置

侧栏「消息发送」显示未读；浏览器标签标题同步数字；新文件在共享文件按钮上显示绿点。

显示角标

聊天上翻时，底部浮出「N 条新消息 · 回到底部」；点击回底并清零。消息未读按消息 id 计算，滚到底也会追平。新文件只在文件夹按钮上点绿点，不把文件数混进消息未读。

拖拽与粘贴

文件拖到窗口任意位置 → 整页浮出带主题色的虚线投放层「松手传到电脑」；落在对话区或抽屉 / 面板区都上传。

  • 拖入文件夹保持目录结构；离开窗口取消。
  • Ctrl/Cmd+V 粘贴截图/文件，仍走全局监听。
  • 页面级 preventDefault，拖偏不会把页面导航走。

＋ 面板

点＋展开四个动作：文件、文件夹、粘贴、共享文件。选择文件立即创建上传卡片并关闭面板；选择共享文件直接打开抽屉 / 面板。

  • 面板不挡住输入内容，收起后草稿还在。
  • 移动端面板高度与键盘互斥，键盘弹起时自动收起。

上传与聊天互不打断

上传只在时间线新增卡片 / 更新进度，不抢输入框焦点、不重排已有消息。滚动位置不因进度更新而跳动。

  • 客户端并发闸 3 个、无进展 125s 回收保持不变；服务端另有上传 16 / 下载 32 并发闸，超限 429。
  • 底部总览条汇总所有在途上传，点击可跳到最新上传卡片。

Markdown、多行输入与主题

消息支持 Markdown：标题、无序 / 有序列表、引用、围栏代码块、行内代码、链接、粗体 / 斜体 / 删除线。输入框为多行 textarea，随内容长高（最高 160px）；桌面 Enter 发送、Shift+Enter 换行，纯触屏 Enter 换行、按钮发送。

外观为 5 套低饱和配色 × 亮色 / 暗色 / 跟随系统；桌面壳对话气泡跟随主题变量，浏览器 / 移动端气泡保持浅底黑字。

空状态与服务状态

空会话：一句「拖个文件，或说句话」+ 两个按钮（上传文件 / 打开共享文件）。服务停止：输入栏上方一条内联提示「服务未启动 · 去启动」，上传与发送禁用。

失联仍走整页「无信号」；移动壳在 v1.2.2 改为「重新启动本机服务」（连电脑模式可回到本机节点，也可到 CC设置改地址）。

键盘与可达性：Enter 发送、Shift 不换行（与现版一致）；F5 刷新文件；Tab 顺序为 时间线 → 输入栏 → 抽屉；触屏无 hover 时动作按钮常显；prefers-reduced-motion 下禁用过渡。

IMPLEMENTATION

把时间线作为新的主干。

现有 App.vue 里聊天与上传是两套数据；微信版需要在它们之上加一层时间线，而不是重写底层上传与聊天。v1.2.2 仍保持单文件区块实现，未拆分为独立组件文件。

// 时间线 = 聊天消息 + 远端文件 + 本次上传文件 / 文件组 const timelineItems = computed(() => { const items = chatMsgs.value .filter(m => m.timestamp > clearedTs.value) .map(m => ({ kind: "msg", key: "m" + m.id, ts: m.timestamp, msg: m })); for (const r of remoteFiles.value) items.push({ kind: "remote", ts: r.ts, r }); for (const u of uploads.value) { if ((u.batchSize || 1) > 3) /* 合并为文件组 */; else items.push({ kind: "file", key: "u" + u.id, ts: u.t0, u }); } return items.sort((a, b) => (a.ts || 0) - (b.ts || 0)); }); // 上传进度原地更新；新文件在面板关闭时点亮绿点 const drawerCollapsed = ref(false); // 桌面 340–400px 抽屉 const fileSheetOpen = ref(false); // 移动 86dvh 面板 const fileDot = ref(false); // 未读按消息 id 计算；页面可见 + 窗口聚焦 + 滚到底才追平 function markChatSeen() { if (view.value !== "transfer") return; if (document.visibilityState !== "visible" || !document.hasFocus()) return; setSeenToLatest(); }

历史文件不伪造成消息：页面刷新后，时间线只保留本次会话真实发生的上传与聊天；完整历史始终在共享文件抽屉里。

1合并导航

侧栏只留「消息发送」，未读徽标迁移；移除移动端悬浮球与底部聊天面板入口。

2时间线主干

timelineItems 合并聊天消息、远端文件、本次上传文件 / 文件组，按时间戳排序；上传 start/progress/done/fail 原地更新卡片。

3文件组

4抽屉 / 面板

6预览与外观

7回归验收

按第 11 节矩阵跑桌面宽/窄、移动端、上传中聊天、拖拽、停服、失联、配对与票据。

改动风险与规避
  • 时间线刷屏：必须做文件组合并；否则一次拖入 200 个文件会把聊天记录淹没。
  • 上传状态与刷新：文件卡片只代表本次会话；刷新后回到抽屉。不要在时间线里伪造历史文件的时间与发送者。
  • 移动端键盘与安全区：输入栏需要 env(safe-area-inset-bottom) 与键盘弹起处理；＋面板与键盘互斥，避免顶起两层。
  • 长按与文本选择：文件行动作不要依赖长按，统一用「⋯」显式按钮，避免与消息文本选择冲突。
  • 未读口径：消息与文件分开计数；文件只点绿点，不把文件数混进消息未读，避免“3 条消息”变成“3 个文件+消息”。
  • 预览与 Range：音视频 / PDF 会发多次 Range，一次性票据首个 206 即失效；应用内预览改用长期 PIN 直连，且不写进浏览器历史。
  • 内联安全：html / svg / xml 不得 inline 打开；服务端 is_inline_safe 与 CSP 的 media-src 同时兜底。
  • 主题与可读性：桌面壳气泡用主题变量跟随皮肤；浏览器 / 移动端保持浅底黑字，避免深色主题下出现深底深字。
10
TRADE-OFFS

微信版 vs 双栏版：最终选择了微信版。

上一版「一页双栏」把文件与聊天并排；这一版把文件放进对话。v1.2.2 已落地微信式结构，双栏提案保留作对照。

维度双栏版（初版提案，未采用）微信版（本方案，已落地）
第一眼文件与消息同时在场，一眼看到两类信息。一条对话，文件以卡片出现，上下文更强。
文件管理常驻列表，排序 / 分页 / 批量删除最顺手。收进抽屉 / 面板，多一次点击，但能力不减。
手机体验文件段 / 消息段切换，操作更像工具。聊天即主页，单手操作最自然，最像微信。
大量上传上传条目在左栏，聊天不受影响。需要文件组，否则时间线会被文件刷屏。
学习成本需要理解“双栏”与可拖动分隔。几乎为零：会发微信就会用。
实现成本布局为主，数据模型基本不动。需要新增时间线模型与文件卡片，改动更深。
RECOMMEND / A

手机优先 → 微信版（已落地）

如果主要场景是手机 ↔ 电脑互传、临时发文件，微信版更顺手；文件管理收进抽屉后仍然完整。v1.2.2 已按此方案实现。

RECOMMEND / B

文件管理优先 → 双栏版（未采用）

如果用户经常批量整理、删除、分享大量文件，常驻文件列表效率更高；微信版会多一次打开抽屉。最终评审选择了微信版的通用性。

HYBRID

也可以各取一半（未采用）

桌面用双栏（文件常驻 + 聊天），手机用微信式（聊天 + 文件面板）。组件共享，但两种形态的学习成本不同；当前实现四端统一为微信式。
