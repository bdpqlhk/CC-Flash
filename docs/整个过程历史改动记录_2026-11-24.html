一、发布流水线

问题修复
v1.2.7 批次误把「缺签名 Secrets 仅告警」改回 ::error + exit 1，publish 失败、Release 停在草稿（与 8115947 及 README 的既定策略冲突）。恢复为只打 ::warning:: 并继续发布未签名/未公证包；资产名精确校验保留；同步更正历史记录表述（9df9327）。
四段 tag（vX.Y.Z.W）的 dmg/exe 文件名只带前三段，与 APK 的完整 tag 命名不一致，publish 精确校验误判「缺少资产」。tauri.conf.json 的 version 必须是 semver（仅三段），故在 desktop job 构建后把 dmg/exe 复制为完整四段 tag 名，删除默认名资产后重传（--clobber）；publish 四项资产统一按完整 tag 校验（a3ebc41、45dabe7）。
API 兜底推送后远端 commit 与本地 refs 哈希分叉，api-push.sh 的 fast-forward 校验拒绝继续。按 GitHub commit JSON 在本地重建远端提交对象，rebase 后重新推送；网络恢复后用正常 git fetch 校准 refs 与标签。

二、Android 安装包版本字段

问题修复
安装器显示 1.0：Tauri CLI 在 Android 上默认写 versionName=1.0，与桌面/应用版本无关。build.gradle.kts 优先读取 CI 注入的 CCFLASH_BUILD_VERSION（完整四段 tag），本地构建按 versionCode 的编码规则反解，安装器显示真实版本。
更隐蔽的问题：versionCode 一直是 1。gen/android 已入库，CI 跳过 tauri android init，tauri.properties 从未生成，Gradle 两个字段都落到模板默认值。versionCode 依次取 tauri.properties → tauri.conf.json > bundle.android.versionCode（release.sh 写入的唯一来源）→ 最后才回退 1；与 versionName 共用同一来源（379f60d）。

四、对端配对码与传输历史

问题修复
输入错误配对码并保存后，后续发送继续复用缓存错码：401 只弹框不清缓存，每次发送都重复提交错码，累计失败触发服务端指数限流（429）；429 又被当作“离线/需要配对”，表现为一直失败且不再提示重新输入。保存前先请求对方 /api/devices 验证：401/429 立即反馈且不落盘；发送遇 401 清除缓存码并重新弹框（输入框留空），遇 429 明确提示“错误次数过多，已被对方临时限流”；文件批量发送按 401/429/403 区分失败原因。
传输历史只有列表，无法按设备/内容查找，也不能清理。新增搜索框（设备名、内容摘要、消息/文件类型），实时过滤并显示匹配数；新增「清空」按钮，使用应用内确认框二次确认；关闭弹框自动清空搜索词，避免下次打开误以为记录变少。

五、手机设置页与访问令牌开关

问题修复
手机 App 设置页仍是 dir-3 的扁平卡片风格，与 dir-5 设计稿不一致（缺少 LOCAL / CONFIG 页头、发丝分隔行、等宽读数、宋体令牌与方色板）。按 dir-5 重构：页头 LOCAL / CONFIG + ACCESS · SYNC · THEME；四行（访问令牌保护 / 系统剪贴板自动同步 / 本机访问令牌 / 外观）+ 版本尾注；方形开关、22px 方色板、宋体大号令牌（点击复制）；保留亮 / 暗 / 跟随系统模式切换。
移动端访问令牌此前被后端硬性禁止关闭（set_access_pin_cmd 直接返回错误），用户无法按需关闭。移除后端限制；设置页开关可关可开，关闭前用应用内确认框提示风险（同 Wi-Fi 无码访问、Android 回环不按应用隔离）；关闭状态写 enabled=0 持久化，重启不复活；重新开启立即生成新码。

六、文件消息持久化

八、设备多选与熄屏保活

问题修复
只能选一台设备；点附近设备卡片会自动弹出「发送到设备」面板。附近设备新增「多选」：sendTargets 数组 + pickPeer，勾选后文本与拖入文件依次直发每台设备；点设备卡片只选中并切换直发，不再弹面板（面板仅由「手动发送」打开）。
手机熄屏后桌面端找不到手机；给手机 App 发消息超时（荣耀等厂商省电策略冻结后台线程/Wi-Fi）。Android 前台服务新增 WifiLock(LOW_LATENCY/HIGH_PERF) + PARTIAL_WAKE_LOCK，首次启动申请忽略电池优化；发送失败提示区分「网络不可达」并提示关闭电池优化。
设备显示在线，但桌面端直发一直失败（提示离线/疑似配对码）。根因之一：同一设备同时发 IPv4 与 IPv6 link-local 宣告，先到的 fe80::%zone 被锁定后另一族会被「换 IP」保护拒绝，而 WebView 直连带 zone 的 IPv6 URL 往往直接失败。现允许同 id / 同令牌从 link-local v6 迁移到 IPv4 并优先 IPv4；失败提示带上目标地址，便于区分「IPv6 地址 / 熄屏冻结 / 配对码」。

九、手机三页 dir-2 信号台改造

问题修复
手机发送 / 设备 / 文件页仍是旧的聊天与抽屉布局，与 dir-2 信号台设计稿不一致。三页按 dir-2 重构：TARGET / UDP / MANIFEST 读数页头、min(236px,62vw) 刻度雷达盘、DEVICES / PORT / LINK 状态格、RSSI 设备行、左昵称时间右正文的消息分栏、方形输入与琥珀发送键、manifest 序号 + 进度条 + 虚线投放区；HISTORY 改为底部 sheet。样式全部限定 .shell.has-mobile-tabs，桌面端与浏览器不受影响。
审查发现：iOS 输入框 <16px 会缩放整页；浅色主题按钮文字对比度不足；目标栏长设备名溢出；文件排序 / 刷新 / 收藏 / 昵称 / 清空入口被样式隐藏；文件行键盘不可达；历史搜索缺少标签。输入框 16px；琥珀按钮文字改 #0b0e0d（浅色 4.59:1）；目标栏省略号 + 雷达盘小屏收缩；保留排序 / 刷新 / 收藏并把昵称、清空、复制、二维码、手动发送收进 ●●● 菜单；文件行补 role=button 与 Enter/Space；历史搜索补 aria-label；设备选择补 aria-pressed。

真实渲染审查需要手动改代码才能看到移动壳。新增仅开发态生效的 ?mobilePreview=1 预览开关（支持 tab / mode / theme 参数），生产构建 tree-shake；本轮用 390×844 真实视口截图逐页复核。

十一、全量代码审查（全平台）

问题处理
全平台 --mono/--sans 等 token 未定义，font 简写静默失效，信号台读数回退 14px。补齐 :root token；移动三页功能字号 11–13px、输入框 16px、未读/危险角标对比度修正。
body 闸门在鉴权前占许可，32 条慢 POST body 可让聊天/剪贴板/分享全部 429。鉴权先于闸门；按来源限 4 条 + 30s 超时，超时/断连释放许可。
IPv6 link-local（fe80::/64）被所有设备共用，限流按 /64 聚合导致一台设备拖累全体。link-local 改用完整地址做限流 key；全局/ULA 仍保留 /64 聚合。
剪贴板 DELETE 无任何限流且每次空删除也落盘/广播。复用 clip_admit；空槽直接返回，不写盘不广播。
发现协议的 IPv6→IPv4 迁移只要求“有一方令牌为空”，可被已知 id 劫持。迁移必须双方令牌非空且一致；空令牌旧版不迁移。
release.sh 的私钥守卫漏 base64 JKS；FORCE_REPUBLISH 无法重建已存在 tag。补 base64 解码魔数检查 + key.properties 文件名；重发前确认 Release 未公开并删除远端旧 tag。
macOS 只配证书、缺公证凭据时 stapler 必然失败。公证四件套只注入非空值；缺凭据时跳过 stapler 并 warning。
移动壳本机服务停止后没有失联层/恢复入口；服务停时批量上传刷屏；预览重试竞态；直发无停滞看门狗；票据预取打满配额。running=false 置 offline 并恢复“重新启动本机服务”；上传前拦截 + toast 上限 5；预览重试复检 seq/文件名；直发 125s 看门狗；预取限前 8 个。
