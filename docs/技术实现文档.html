3Rust 服务层 · 全局状态与生命周期

3.1 全局状态（OnceLock + Mutex / Atomic）

状态类型说明
chat_log()Mutex<VecDeque<ChatMsg>>聊天记录，上限 200 条（id 自增、昵称、内容、时间戳、IP）

3.2 启动流程 start(preferred: Option<u16>)

  1. 已在运行 → 直接返回当前端口（幂等）；
  2. 创建共享目录（失败报「共享目录不可用」）；
  3. 候选端口序列：preferred, preferred+1..+20 → 再扫 1688..1707，去重后逐个 bind("0.0.0.0", p)；
  4. 记录端口 → 写日志「服务已启动 端口 N 目录 …」/「首选端口 X 被占用，已顺延至 N」/「共享目录当前 N 个文件 · 访问地址: …」；
  5. router(share).into_make_service_with_connect_info::<SocketAddr>() 注入连接信息（日志取来源 IP 用）；
  6. axum::serve + with_graceful_shutdown（oneshot 通道），任务句柄存入 running_slot。

3.3 停止 / 自启 / 状态

  • stop()：取走 handle → 发 shutdown → 写「服务已停止」；task 为 daemon 语义不等待；
  • autostart()：应用启动时 start(None)，失败只打 stderr 不阻断 GUI；
  • status() → (running, PORT, lan_ip())。

3.4 局域网 IP 探测 lan_ip()

if-addrs 枚举全部网卡 → 排除隧道类(utun/tun/tap/wg/ppp/vethernet/docker/vmnet/virbr)
→ IPv4 非回环; RFC1918+link-local 进「私网池」, bridge*(macOS 互联网共享)降为末位候选
→ 优先级: UDP 探测结果落在私网池(默认路由准头, 双网卡场景) > 私网池首个 > 其他网卡首个
  > bridge > 探测值 > 127.0.0.1

旧实现仅一次 UDP connect 探测（源地址由默认路由决定）：开 VPN/TUN/代理的机器返回隧道地址（如 10.8.0.2），二维码手机扫码必失败；IPv6-only 静默回落 127.0.0.1。现枚举真实网卡——VPN 虚拟网卡被排除，bridge100（手机直连 Mac 热点时唯一可达地址）作为末位候选保留。每次调用都重新枚举——这是"IP 变化检测"需求的基石：服务不重启也能拿到最新 IP。

5关键流程实现

5.1 上传（并行分片 + 范围账本 + 断点续传 + 目录结构保留）

HEAD 头校验 → percent_decode(X-Filename) → safe_rel_path(相对路径逐段校验, 保留形态与系统垃圾文件
  [.DS_Store/._*/Thumbs.db/desktop.ini, 防目录文件名元数据泄露]、控制字符(CR/LF/NUL 等,
  Windows 文件名非法且跨端不一致)与 RTL 覆写符(U+202A-E, 防"exe.jpg"反转伪装扩展名)仅上传拒绝) ─非法→ 400
→ X-Upload-Id 消毒: 长度≤200 且无控制字符(meta 首行注入防线) ─非法→ 400
→ #[cfg(windows)] MAX_PATH(260) 预检(按 UTF-16 code unit 计) ─超限→ 400
→ (size-offset) > fs2::available_space ─是→ 400「上传拒绝」
→ 会话私有断点文件: <名>.<idhash(FNV-1a)>.ccpart —— 每会话独立, 接管/并发互不污染
→ PHASE1(短锁 part_lock, 等锁 10s 超时 → 409):
   meta 三行解析: 会话 id / 最终落盘名(dedup 改名) / 账本 JSON(offset→len)
   offset==0: 完成记录命中(最终名大小吻合)→直接 done:true
              他人断点 30s 内仍写入→409 busy; 否则接管:
              truncate + set_len(size) 预分配稀疏 + 写 meta「id\nchosen\n{}」
              chosen = dedup_rel_name(同名自动改名 (1)(2) 顺延, 持锁决策不撞名)
   offset>0:  空 id→409; part 不在→完成记录核对(按**最终名**)/409
              账本会话→任意格子直接写(已预分配); 旧版顺序会话→长度对齐(跨版本兼容)
→ 越界预检(canonicalize 最近存在祖先) + create_dir_all + 建后复验(防 TOCTOU 符号链接)
→ OpenOptions(truncate=false, 分片绝不截断他人区间) → seek(offset) → 放锁 ← 并行的关键
→ loop: 空闲超时 120s / body_stream.next()
   ├─ 写失败→500 / 连接断开·空闲→502/504{received} / 超 size→400 / 磁盘不足→507
   └─ 正常写入(received = offset+已写; 账本会话各连接区间不相交)
→ PHASE3(短锁): 重读 meta 校验会话归属(流式期间被接管→409) → 账本登记{offset:len}(幂等)
   → coverage<size → 200{received:coverage,done:false}
   → 收齐 → sync_all(inode 级, 各连接脏页一并落盘) → rename 转正(5×300ms 退避,
     防 Windows 占用) → meta 保留为完成记录(TTL 7 天回收) → 日志+广播 files:changed
   → 200{ok,received:coverage,done:true,final:最终名}

并发模型：锁分三段（建会话/登记账本/转正持锁，流式收包不持锁），多连接同时写同一文件的不相交区间；客户端切 16MB 格子 × 3 连接（iOS 单连接 RTO 停摆免疫）。断点生命周期：服务启动只清理超过 7 天的会话断点（TTL 按 mtime 真实年龄，未来 mtime 保留）。

断点生命周期：服务启动只清理超过 7 天的 .ccpart/.meta（TTL，按 now−mtime 真实年龄判定；未来 mtime（系统时钟被改）按未过期保留，宁多留不误删）——期内保留使进程/系统重启后重选同一文件可凭会话指纹续传（Android 退后台被杀不再无声归零）；过期才回收磁盘。

5.2 下载（流式 + Range 断点续传）

safe_rel_path(读路径: 保留形态放行, 否则既有 aux.pdf 等取不回) → safe_join_existing
→ metadata.is_file() 校验(目录在 Unix 上 open 成功但读到 EISDIR 中途断流 → 400)
→ 解析 Range(单区间 "N-" / "N-M"; 多区间/畸形忽略按整体 200; start≥size → 416 + bytes */size)
→ seek(start) → take(end_excl - start)(N-M 必须截断: 不截断读到 EOF 会多发字节,
  与 CONTENT_LENGTH 不符破坏 HTTP 分帧) → BufReader → ReaderStream 1MB
→ 日志「下载 (大小) ← IP[ · 续传自 N]」
→ headers: Content-Type / Accept-Ranges: bytes / Content-Disposition(RFC5987) /
   Cache-Control: no-cache / Content-Length(显式) [206 时附 Content-Range: bytes s-e/size]

浏览器断下重试携带 Range: bytes=N- 时返回 206 从断点继续——10GB 文件传到 8GB 断掉不再从零重来。

6路径安全设计

所有接受文件名的接口（下载/删除/上传/复制/断点查询）统一走两道防线：

  1. safe_rel_path(raw)（输入应为已解码字符串）：把 \ 归一为 / → 逐段校验：拒绝空 / "." / ".." / 首尾空格 / Windows 非法字符（/:*?"<>|，其余平台统一保证跨端一致）/ 结尾点 / 内部产物后缀（.ccpart/.meta）→ 段数上限 8（与列表递归深度一致）→ 以 / 连接返回相对路径；
  2. safe_join_existing(share, name)：拼路径后 canonicalize()，校验结果必须以共享目录 canonicalize 前缀开头（防符号链接/编码绕过越界）。
上传的额外预检上传可能创建新路径：建目录前对「最近存在的祖先」做 canonicalize 越界校验——create_dir_all 会跟随符号链接，先建后查会把目录建到共享目录之外。断点查询（upload_progress）纯只读、不创建任何目录（防任意查询串刷出空目录树）。
解码边界axum 的 Path/Query 提取器自带一次 percent 解码；X-Filename 请求头不经提取器，由 upload 处理解一次再传入。safe_rel_path 本身不再解码——避免含字面 %XX 的文件名被双重解码后指向别的文件。

6.1 访问令牌与请求准入（中间件）

  • 本机来源豁免：is_local_source = 回环地址 ∪「源 IP 绑定 UDP socket 试探」（同机浏览器经局域网 IP 访问时源地址是网卡 IP 而非 127.0.0.1，只判回环会把电脑前的人锁在外面）；伪造源地址需完成 TCP 握手（收不到 SYN-ACK），不可冒充。双栈监听（[::]）下 IPv4 连接的源地址是 v4-mapped 形态（::ffff:a.b.c.d），而 is_loopback/UDP 探测只认纯 v4——统一经 normalize_peer 折回纯 IPv4 再判定（v1.1.4 修复：此前桌面壳经 127.0.0.1 的控制接口调用被误判远程 403，"服务日志"面板因此全瞎）；
  • 控制接口仅限本机：/api/control/*（启停/日志）非回环来源一律 403；
  • Host/Origin 守卫：Host 必须是 IP / localhost / *.local（挡 DNS 重绑定）；带 Origin 的请求只放行自身与 tauri WebView 源（挡跨源 CSRF）；
  • 访问令牌（可选）：开启后非本机的 API/WS 请求必须携带 ?pin= 或 X-Access-Pin；6 位数字码（时间纳秒^进程id^自增序号经 splitmix64 扩散），状态落盘重启不静默失效；导航请求（Accept 含 text/html）回可输入配对码的 HTML 中转页而非裸 JSON；
  • 防爆破退避（v1.1.4）：只统计「实际提交了配对码」的尝试（无码的后台轮询不计额度）；同一 IP 连续失败 8 次后指数退避（15s 起步每次翻倍、封顶 1h）——锁定窗内一律 429，正确码也拒绝（若放行，对/错码响应可区分，攻击者伪造 Accept 头即可全速逐个试码，退避形同虚设）；锁定中不记数不延长（轰炸无法续窗），配对成功立即清零；逐 IP 计数使攻击者只能锁住自己的源地址。导航请求在锁定窗内回可重试的 429 表单页；
  • 日志卫生：日志行剥 CR/LF 防伪造注入、单行硬截断 400 字符；查询串中的 pin 一律脱敏为 pin=***。

9.4 上传实现（分片 + 断点续传 + 整目录 + 并发闸）

  • 并行分片（v1.1.6 定策）：文件切 16MB 格子（UPLOAD_CELL）× 3 连接并发（UPLOAD_WORKERS），文件级并发闸 2（WebKit 每 host 6 连接预算）。依据：实测 iPhone 对单条上传连接会周期性僵死（RTO 退避，单次停摆 ~63s，期间 WS/下行畅通 = 链路活仅此连接死），多连接互相掩护；断点粒度随之细化到单格。会话代次：已完成文件主动重传换新会话 id（fp|ts，localStorage 记忆），服务端同名自动改名落为新副本——"重传=要新副本"，断点续传仍按原会话按格接力；
  • XHR 替代 fetch：fetch 无上传进度事件；XHR upload.onprogress 提供实时已发字节数（单连接速率展示），进度百分比只认服务端账本覆盖值（每 3s 轮询断点长度封顶，防"已交网络"虚报后回落）；双信号看门狗：onprogress 到达或服务端断点增长均续命（15s），断点收齐切等响应宽限（UPLOAD_RESPONSE_GRACE_MS 90s，覆盖 iOS 冻结）——传输中永不误杀，真停滞才中止走续传；
  • 并发闸（5 路）：浏览器（尤其 Safari/WebKit）每 host 仅 6 条 HTTP/1.1 连接且 WS/轮询/缩略图已占槽——一次选数百文件全并发时排队请求会被误杀集体报"上传中断"；入队真正排队（waiting 状态真实生效）；
  • 4xx 快速失败：路径过长等确定性业务错误直接报错（408/409/429 例外仍重试），不做 8×1.5s 空转；
  • 断点续传：会话 id = 文件名|大小|lastModified 稳定指纹（name 做 encodeURIComponent——请求头是 ByteString，原始中文会抛 TypeError）；开传前与每次失败后 GET /api/upload_progress（携带 size 参数）以服务端断点为准重排，查询失败（null）保持当前 offset 不动（防网络抖动误将数 GB 断点清零）；断点已转正且大小吻合直接确认完成（响应冻结场景不从零重传）；连续失败 8 次（成功一片清零）报错；
  • 并发闸（5 路）：浏览器（尤其 Safari/WebKit）每 host 仅 6 条 HTTP/1.1 连接且 WS/轮询/缩略图已占槽——一次选数百文件全并发时排队请求会被 30s 超时误杀集体报"上传中断"；入队真正排队（waiting 状态真实生效）；
  • 4xx 快速失败：路径过长等确定性业务错误直接报错（408/409/429 例外仍重试），不做 8×1.5s 空转；
  • 断点续传：会话 id = 文件名|大小|lastModified 稳定指纹（name 做 encodeURIComponent——请求头是 ByteString，原始中文会抛 TypeError）；开传前与每次失败后 GET /api/upload_progress 以服务端断点为准重排，查询失败（null）保持当前 offset 不动（防网络抖动误将数 GB 断点清零）；连续失败 8 次（成功一片清零）报错；
  • 整目录：拖拽走 webkitGetAsEntry 递归收集（混合拖入兼容、空文件夹给提示），「选择文件夹」走 webkitdirectory（iOS/iPadOS 无此能力入口隐藏），相对路径经 webkitRelativePath 保留；
  • 下载：桌面/移动壳一律 HEAD 预检（8s 超时）+ 锚点原生流式下载（壳内由 on_download 落盘系统下载目录 + 事件提示，文件名三道防线防路径逃逸）；手机浏览器 ≤50MB 走 blob（有完成时机），>50MB 原生；HTTP 错误如实报错；微信内打开顶部常驻引导条（下载被拦 → 在浏览器打开）；
  • 完成侧合并节流：非手动 loadFiles 800ms 内合并（批量上传完成风暴不再数百次串行全量拉取）；files:changed WS 事件同享该节流。

frontend_config() 把运行参数随三个出口下发——/api/info、/api/control/status、桌面 invoke control_status_cmd（同时携带 version）：

{ "ip": "...", "port": 1688, "running": true,
  "version": "1.0.0",
  "config": { "nickMax": 20, "msgMax": 2000, "defaultNick": "匿名用户",
              "chatMax": 200, "poll": { "chat": 3000, "files": 5000, "status": 2500, "logs": 2000 } } }
  • 前端响应式 cfg 对象：config.js 值仅作启动兜底；每次状态响应经 applyServerConfig() 合法性校验后覆盖（非法值回退兜底）；
  • 下发的轮询间隔与当前不同 → startPolling() 自动重排定时器；
  • 收益：改 config.rs + 重启服务，所有网页端自动跟随，无需重新构建前端。

10.3 版本号单一来源

  • 唯一来源：Cargo.toml [package] version；
  • tauri.conf.json 省略 version 字段（Tauri 构建自动回退读 Cargo.toml）；
  • APP_VERSION = env!("CARGO_PKG_VERSION") 编译期取同源值，随状态接口下发；
  • 前端侧边栏展示接口下发的版本号，更新检查亦以此比较——发版只改 Cargo.toml 一处。

npm run tauri build

11.1 CI 自动发版

  • .github/workflows/release.yml：推送 v* 标签触发——desktop(macos/windows, tauri-action 建 Release 并上传) + android(ubuntu, needs: desktop 但 if: always() 不连坐)；permissions: contents: write 为必需（GITHUB_TOKEN 默认只读）；Android 需先接受 SDK 许可并定位 NDK_HOME；
  • Android 构建与签名：tauri android build --apk --split-per-abi 按 4 个 ABI 分包（flavor arm64/arm/x86/x86_64 → 文件名映射 arm64-v8a/armeabi-v7a/x86/x86_64）。配置 ANDROID_KEYSTORE_BASE64 / ANDROID_KEYSTORE_PASSWORD / ANDROID_KEY_ALIAS / ANDROID_KEY_PASSWORD 四个 Secrets 后：keystore 解码到 $RUNNER_TEMP、导出 CC_KEYSTORE_* 环境变量 → 入库的 gen/android/app/build.gradle.kts 中 signingConfigs.release 读取并挂到 release 变体（固定证书，版本间可覆盖安装）；未配置时退回 --debug 构建（runner debug keystore，各版本证书不同，CI 出 warning）。release 变体显式 usesCleartextTraffic=true——应用全部流量是有意的局域网明文 HTTP，否则 API 全部被 ERR_CLEARTEXT_NOT_PERMITTED 拦死；
  • 发布保护：产物 find ! -name "*unsigned*" 兜底（缺签名直接 CI 失败）；desktop job 失败时 APK 仍上传但 Release 保持草稿（draft: needs.desktop.result != 'success'），人工确认后手动 Publish；
  • 一键发版：./scripts/release.sh X.Y.Z [提交信息]——升版本/提交/打标签/推送（3 次重试 + GitHub API 建 tag 引用兜底，应对 git 443 通道抖动），并轮询验证 Actions 已触发；
  • 注意：git 推送标签与 main 同批推送存在事件偶发丢失的情况，脚本采用分步推送 + 触发验证来规避。

12设计取舍与已知事项

事项说明
无鉴权可信局域网模型，控制接口与文件接口均无鉴权；切勿暴露公网
推送 + 轮询双通道聊天/列表/状态走 WebSocket 推送（15s 心跳 + 10s 看门狗强制重连），轮询降级兜底；日志仍 2s 轮询（仅桌面控制台消费，不值得占 WS）

更新检查前端直连 GitHub Releases API，失败一律静默；应用内自更新（签名+自动重启）留作演进
