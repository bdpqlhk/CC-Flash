3Rust 服务层 · 全局状态与生命周期

3.1 全局状态（OnceLock + Mutex / Atomic）

状态类型说明
chat_log()Mutex<VecDeque<ChatMsg>>聊天记录，上限 200 条（id 自增、昵称、内容、时间戳、IP）
req_log()Mutex<VecDeque<String>>服务日志，上限 1000 条
PORTAtomicU16当前服务端口
running_slot()Mutex<Option<ServerHandle>>ServerHandle = { port, shutdown: oneshot::Sender, task: JoinHandle }
share_dir()—共享目录（默认 ~/CC-Flash，可 set）

3.2 启动流程 start(preferred: Option<u16>)

  1. 已在运行 → 直接返回当前端口（幂等）；
  2. 创建共享目录（失败报「共享目录不可用」）；
  3. 候选端口序列：preferred, preferred+1..+20 → 再扫 8765..8785，去重后逐个 bind("0.0.0.0", p)；
  4. 记录端口 → 写日志「服务已启动 端口 N 目录 …」/「首选端口 X 被占用，已顺延至 N」/「共享目录当前 N 个文件 · 访问地址: …」；
  5. router(share).into_make_service_with_connect_info::<SocketAddr>() 注入连接信息（日志取来源 IP 用）；
  6. axum::serve + with_graceful_shutdown（oneshot 通道），任务句柄存入 running_slot。

3.3 停止 / 自启 / 状态

  • stop()：取走 handle → 发 shutdown → 写「服务已停止」；task 为 daemon 语义不等待；
  • autostart()：应用启动时 start(None)，失败只打 stderr 不阻断 GUI；
  • status() → (running, PORT, lan_ip())。

3.4 局域网 IP 探测 lan_ip()

UdpSocket::bind("0.0.0.0:0") → connect("10.255.255.255:1") → local_addr().ip()

UDP connect 不实际发包，由路由表判定出口网卡 IP；失败回退 127.0.0.1。每次调用都重新探测——这是"IP 变化检测"需求的基石：服务不重启也能拿到最新 IP。

5关键流程实现

5.1 上传（流式 + 预检 + 自清理）

HEAD 头校验 → safe_name(X-Filename) ─非法→ 400
→ X-File-Size > fs2::available_space ─是→ 400 + 日志「上传拒绝」
→ path.exists()? 记录覆盖标记
→ File::create（失败→500+日志）
→ 日志「上传开始 (声明大小) ← IP · 覆盖同名文件」
→ while chunk = body_stream.next(): 写入累加 written
   ├─ 写失败 → remove_file + 日志「上传失败…已清理半截文件」→ 500
   └─ 客户端断开 → remove_file + 日志「上传中断…已清理半截文件」→ 500
→ sync_all → 日志「上传完成 (大小, 耗时ms)」→ 200 {ok,name,size}

5.2 下载

safe_name → safe_join_existing(共享目录内且存在) → File::open
→ 日志「下载 (大小) ← IP」
→ headers: Content-Type / Content-Disposition(attachment; filename*=UTF-8'') /
   Cache-Control: no-cache / Content-Length(显式)
→ Body::from_stream(ReaderStream 1MB)

5.3 聊天收发

POST: trim → 空消息 400 → 昵称 chars().take(20)（空则"匿名用户"）→ 消息 take(2000)
    → id = 上一条+1 → ChatMsg{..., ip} 入队（>200 pop_front）
    → 日志「聊天 {昵称}: {内容前40字}… ← IP」
GET:  返回 Vec<ChatMsg>

5.4 删除

safe_name → safe_join_existing → remove_file
→ 成功: 日志「删除 {名} ← IP」；失败: 日志「删除失败 …」→ 500

6路径安全设计

所有接受文件名的接口（下载/删除/上传/复制）统一走两道防线：

  1. safe_name(raw)：percent_decode → 把 \ 归一为 / → 取 Path::file_name() basename → 拒绝空 / "." / ".."；
  2. safe_join_existing(share, name)：拼路径后 canonicalize()，校验结果必须以共享目录 canonicalize 前缀开头（防符号链接/编码绕过越界）。
为什么上传不需要第二道上传的落盘路径 = share.join(name)，name 已经是 basename（第一道保证不越界），且目标固定在共享目录根部。

7日志系统实现

7.1 数据结构与格式

  • 环形缓冲 VecDeque<String>，上限 1000；
  • 前缀 [HH:MM:SS.mmm]——chrono::Local::now().format("%H:%M:%S%.3f") 本地时间；
  • 业务行由各 handler 主动写入；请求行由中间件统一写入。

7.2 请求日志中间件（from_fn）

提取: ConnectInfo<SocketAddr>(来源) · method · path · query
      · X-Nickname 昵称 · User-Agent → device_kind(设备)
计时 → next.run → 计算 ms / 状态码 / Content-Length(人类可读, 无则 "-")
噪音豁免(GET): NOISY_GET_PATHS 常量数组(config.rs) · /favicon.ico
               = /api/chat · /api/info · /api/files · /api/control/logs
               (与前端 config.js 轮询路径一一对应, 前端调整轮询需同步)
输出: "GET /path?q → 200 1.5 KB 12ms ← 10.161.x.x (Mac Chrome-2569·Mac)"

7.3 设备识别 device_kind(ua)

UA 关键字映射：iPhone / iPad / Android / MicroMessenger→微信内置 / Macintosh→Mac / Windows / Linux，均未命中→「未知设备」。昵称存在时显示 {昵称}·{设备}。

9.9 失联处理与服务状态拦截

  • serviceDown()：桌面看 running（启停按钮直控）、网页看 offline（失联判定）——删除（单/批/确认兜底三处）、分享、复制链接均先拦截并友好提示；
  • 失联判定时清空 allFiles / 聊天消息 / 未读 / 勾选，服务恢复后轮询自动重新拉取，页面自愈；
  • loadFiles 在途竞争：reloadQueued 补拉队列，删除后的刷新绝不丢失（否则在途旧响应会把已删文件"弹回"列表）。

9.10 版本更新检查（update.js）

  • fetchLatestRelease()：直连 api.github.com/repos/{repo}/releases/latest（免鉴权、支持跨域、AbortController 8s 超时），任何失败返回 null 由调用方静默处理；
  • isNewer()：语义化比较（剥 v 前缀/-beta 后缀、分段数值、短方补 0）；
  • 触发：启动 3s 后静默检查 + localStorage 24h 频控（wft-update-check）；「关于」卡手动检查（失败有明确提示）；发现新版弹框，「前往下载」走 open_url_cmd 打开 Release 页。

10.2 参数下发机制

frontend_config() 把运行参数随三个出口下发——/api/info、/api/control/status、桌面 invoke control_status_cmd（同时携带 version）：

{ "ip": "...", "port": 8765, "running": true,
  "version": "1.0.0",
  "config": { "nickMax": 20, "msgMax": 2000, "defaultNick": "匿名用户",
              "chatMax": 200, "poll": { "chat": 3000, "files": 5000, "status": 2500, "logs": 2000 } } }
  • 前端响应式 cfg 对象：config.js 值仅作启动兜底；每次状态响应经 applyServerConfig() 合法性校验后覆盖（非法值回退兜底）；
  • 下发的轮询间隔与当前不同 → startPolling() 自动重排定时器；
  • 收益：改 config.rs + 重启服务，所有网页端自动跟随，无需重新构建前端。

10.3 版本号单一来源

  • 唯一来源：Cargo.toml [package] version；
  • tauri.conf.json 省略 version 字段（Tauri 构建自动回退读 Cargo.toml）；
  • APP_VERSION = env!("CARGO_PKG_VERSION") 编译期取同源值，随状态接口下发；
  • 前端侧边栏展示接口下发的版本号，更新检查亦以此比较——发版只改 Cargo.toml 一处。

mDNS 域名发现		目标：IP 变化后旧地址失效，改用固定名 http://wft.local:{port} 自动跟随。实现要点：mdns-sd = "0.13"（纯 Rust 无系统依赖）在 start() 时注册 _http._tcp 服务实例（host=wft.local.，addr=当前 IP），后台任务比对 lan_ip() 变化后 unregister+re-register，stop() 时注销；断连横幅加提示语。工作量：60–80 行 Rust，约半天。已知边界：Android 浏览器不解析 .local（系统限制）；禁多播网络失效；同网段多实例需冲突改名（wft-xxxx.local）；端口变更仍需手写（浏览器不读 SRV）。优先级中低——iPhone/桌面用户收益明确，安卓场景现有断连横幅+二维码路径更可靠。
