3.2 启动流程 start(preferred: Option<u16>)

  1. 已在运行 → 直接返回当前端口（幂等）；
  2. 创建共享目录（失败报「共享目录不可用」）；
  3. 候选端口序列：preferred, preferred+1..+20 → 再扫 1688..1707，去重后逐个绑定；open_lan=true 时走 bind_dualstack（[::] 双栈 + v4 连通自检，失败回落 0.0.0.0），移动端/桌面现在始终开放局域网，旧 open_lan=false 不再改变监听地址；
  4. 记录实际生效端口 →（本次指定过端口时）写端口偏好 → 写日志「服务已启动 端口 N 目录 …」/「首选端口 X 被占用，已顺延至 N」/「共享目录当前 N 个文件 · 访问地址: …」；open_lan 偏好持久化，切换后重启服务生效；
  5. router(share).into_make_service_with_connect_info::<SocketAddr>() 注入连接信息（日志取来源 IP 用）；
  6. axum::serve + with_graceful_shutdown（oneshot 通道），任务句柄存入 running_slot。

3.3 停止 / 自启 / 状态

  • stop()：取走 handle → 广播 ws_kick → 发 shutdown → 写「服务已停止」；在途上传随之回滚，task 为 daemon 语义不等待；
  • autostart()：应用启动时回放上次端口 start(last_preferred_port())，失败只打 stderr 不阻断 GUI；
  • status() → (running, PORT, lan_ip())。

3.4 局域网 IP 探测 lan_ip()

if-addrs 枚举全部网卡 → 排除隧道类(utun/tun/tap/wg/ppp/vethernet/docker/vmnet/virbr)
→ IPv4 非回环; RFC1918+link-local 进「私网池」, bridge*(macOS 互联网共享)降为末位候选
→ 优先级: UDP 探测结果落在私网池(默认路由准头, 双网卡场景) > 私网池首个 > 其他网卡首个
  > bridge > 探测值 > 127.0.0.1

旧实现仅一次 UDP connect 探测（源地址由默认路由决定）：开 VPN/TUN/代理的机器返回隧道地址（如 10.8.0.2），二维码手机扫码必失败；IPv6-only 静默回落 127.0.0.1。现枚举真实网卡——VPN 虚拟网卡被排除，bridge100（手机直连 Mac 热点时唯一可达地址）作为末位候选保留。每次调用都重新枚举——这是"IP 变化检测"需求的基石：服务不重启也能拿到最新 IP。

4Rust 服务层 · HTTP 路由全表

方法路径功能要点

5关键流程实现

5.1 上传（单请求整文件直传 + 同名顺延 + 目录结构保留）

并发闸: upload_permits 16 个槽位, 超限立即 429(不排队, 防空闲连接耗尽 fd)
→ HEAD 头校验 → percent_decode(X-Filename) → safe_rel_path(相对路径逐段校验, 保留形态与系统垃圾文件
  [.DS_Store/._*/Thumbs.db/desktop.ini, 防目录文件名元数据泄露]、控制字符(CR/LF/NUL 等,
  Windows 文件名非法且跨端不一致)与 RTL 覆写符(U+202A-E, 防"exe.jpg"反转伪装扩展名)仅上传拒绝) ─非法→ 400
→ #[cfg(windows)] MAX_PATH(260) 预检(按 UTF-16 code unit 计, 查最终落盘路径) ─超限→ 400「路径过长」
→ size>0 且 size + 256MB 安全余量 > fs2::available_space ─是→ 400「上传拒绝」
→ 越界预检(canonicalize 最近存在祖先, 先查后建防符号链接) + create_dir_all + 建后复验(TOCTOU, 越界回滚空目录)
→ **file_op_lock 临界区**: create_new 原子占位(绝不覆盖): AlreadyExists → dedup_rel_name 从**原名**
   重算第一个空闲变体 (1)(2)… 重试 └─ Windows: 变体名二次查 MAX_PATH(260) → 超限→400「改名后路径过长」
→ **marker 长度预检**: base.len() + 6 > 249 → 400「文件名过长（含上传标记超出系统上限）」
   (.{名}.ccup 比成品名多 6 字符, 接近 NAME_MAX 的合法文件名否则会卡在标记创建)
→ 写首字节前创建 .{名}.ccup **完整性标记**: 首行 ccflash-v1: + 16 位会话令牌 / 第二行声明大小
   (旧版裸 16hex 标记只做安全迁移; "ok" = 上传成功但标记删除失败; 空标记 = 崩溃在建标记后写令牌前;
    非以上形态一律视为用户自己的 .x.ccup, 绝不触碰/覆盖)
   同一临界区内 active_uploads 计数+1 —— 占位/标记/登记与 DELETE 的复查/删除互斥, 无 TOCTOU 假成功
→ body 流式落盘: body.into_data_stream() 逐帧 write_all(零内存膨胀); 每 64MB 复查磁盘剩余(低于 256MB 余量→507+清理)
   ├─ 写失败/断开/空闲 120s/总时长 6h/**低速闸(连续 60s 增量 < 16KB)**/磁盘不足/收到停服信号
   │   → drop 句柄后 abort(仅标记仍属本会话才删成品+标记, 计数-1)
   └─ 正常结束 → sync_all(失败→清理+500) → **written ≠ 声明 size → 按不完整清理+400**
        → 删标记(失败则写入 "ok", 启动见 ok 只删标记保成品) → 在途计数-1 → 日志 → 200{ok, name, final, size}
   在途保护: DELETE 见 active_uploads 计数或**合法上传令牌**标记 → 409「上传中」
             ("ok" 标记与用户自建 .ccup 不锁文件; "ok" 顺带回收)
   停服: stop() 广播停服信号 → 在途上传立即回滚; start() 前等待 active_uploads 清空, 避免启动清理误删仍在写的文件

语义：一个文件 = 一个请求 = 一条连接，整文件即"最大的分片"，服务端不维护任何分片/账本/会话状态（v1.1.8 回归 1.1.2 直传语义，仅保留 1.1.5 起的同名自动改名；v1.2.2 增加并发/低速闸与 marker 状态机）。锁屏防中断由前端 Wake Lock + 2px 视频通路保活承担（9.4）。/api/upload_progress、/api/upload_cancel 与启动 TTL 清理仅为 v1.1.5-1.1.7 旧版遗留 .ccpart 服务；清理只认带会话指纹的命名（<name>.<16hex>.ccpart/.meta 与 .ccpart.meta.tmp），同名同后缀的普通用户文件不删；按 now−mtime 真实年龄判定，未来 mtime（系统时钟被改）按未过期保留，宁多留不误删。

5.2 下载（流式 + Range 断点续传）

并发闸: download_permits 32 个槽位, 超限立即 429(每条下载固定占流式缓冲/fd)
准入(中间件): 有效分享票据先于访问码放行(否则开 pin 时分享链接先吃 401, 接收方被迫索要全站码);
  票据 peek 不销, **任意成功 GET(含 206 Range) 后即焚** —— 旧实现只认起始 0,
  `Range: bytes=1-` 可无限重复拉取余下全文; HEAD 预检不销票; 断点续传后续请求需重新索取链接;
  无效票据按 IP 限流(20 次/10 分钟); 文件名逐段 percent 解码后再校验(中文名票据可匹配, %2E%2E 仍被拦)
safe_rel_path(读路径: 保留形态放行, 否则既有 aux.pdf 等取不回) → safe_join_existing
→ metadata.is_file() 校验(目录在 Unix 上 open 成功但读到 EISDIR 中途断流 → 400)
→ 解析 Range(单区间 "N-" / "N-M"; 多区间/畸形忽略按整体 200; start≥size → 416 + bytes */size)
→ seek(start) → take(end_excl - start)(N-M 必须截断: 不截断读到 EOF 会多发字节,
  与 CONTENT_LENGTH 不符破坏 HTTP 分帧) → BufReader → ReaderStream 1MB
→ 应用内预览: ?inline=1 且扩展名在 is_inline_safe(图片/PDF/文本/音视频; 排除 html/svg/xml)
   → Content-Disposition: inline(其余一律 attachment, 防同源脚本执行)
→ 日志「下载 (大小) ← IP[ · 续传自 N]」
→ headers: Content-Type / Accept-Ranges: bytes / Content-Disposition(RFC5987) /
   Cache-Control: no-cache / Content-Length(显式) [206 时附 Content-Range: bytes s-e/size]

浏览器断下重试携带 Range: bytes=N- 时返回 206 从断点继续——10GB 文件传到 8GB 断掉不再从零重来。

safe_rel_path → safe_join_existing → file_op_lock 内复查在途 → 删除

6路径安全设计

所有接受文件名的接口（下载/删除/上传/复制/断点查询）统一走两道防线：

  1. safe_rel_path(raw)（输入应为已解码字符串）：把 \ 归一为 / → 逐段校验：拒绝空 / "." / ".." / 首尾空格 / Windows 非法字符（/:*?"<>|，其余平台统一保证跨端一致）/ 结尾点 / 内部产物后缀（.ccpart/.meta）→ 段数上限 8（与列表递归深度一致）→ 以 / 连接返回相对路径；
  2. safe_join_existing(share, name)：拼路径后 canonicalize()，校验结果必须以共享目录 canonicalize 前缀开头（防符号链接/编码绕过越界）。
删除符号链接的边界删除接口拿到的是 canonical 目标路径，直接 remove_file 会删到共享目录内的另一个真实文件；删除前用 symlink_metadata 判断原路径，是链接就只删链接本身。
上传的额外预检上传可能创建新路径：建目录前对「最近存在的祖先」做 canonicalize 越界校验——create_dir_all 会跟随符号链接，先建后查会把目录建到共享目录之外。断点查询（upload_progress）纯只读、不创建任何目录（防任意查询串刷出空目录树）。
解码边界axum 的 Path/Query 提取器自带一次 percent 解码；X-Filename 请求头不经提取器，由 upload 处理解一次再传入。safe_rel_path 本身不再解码——避免含字面 %XX 的文件名被双重解码后指向别的文件。

6.1 访问令牌与请求准入（中间件）

  • 本机来源豁免：is_local_source = 回环地址 ∪「源 IP 绑定 UDP socket 试探」（同机浏览器经局域网 IP 访问时源地址是网卡 IP 而非 127.0.0.1，只判回环会把电脑前的人锁在外面）；伪造源地址需完成 TCP 握手（收不到 SYN-ACK），不可冒充。双栈监听（[::]）下 IPv4 连接的源地址是 v4-mapped 形态（::ffff:a.b.c.d），而 is_loopback/UDP 探测只认纯 v4——统一经 normalize_peer 折回纯 IPv4 再判定（v1.1.4 修复：此前桌面壳经 127.0.0.1 的控制接口调用被误判远程 403，"服务日志"面板因此全瞎）；
  • 控制接口仅限本机：/api/control/*（启停/日志）非回环来源一律 403；
  • 局域网始终开放：旧版安全模式偏好不再生效，服务始终绑定局域网；移动端用自动生成的本机访问令牌保护。
  • Host/Origin 守卫：Host 必须是 IP / localhost（已移除 *.local——同 Wi-Fi 攻击者可自架 mDNS 应答做 DNS 重绑定，让受害者浏览器同源直连本机服务、源地址豁免 pin；二维码本就下发 IP，收紧无损正常路径）；带 Origin 的请求只放行自身与 tauri WebView 源（挡跨源 CSRF）；
  • 公网来源守卫：非本机且非私网/链路本地/ULA 的地址，在未开启访问令牌时直接 403——主机有公网 IPv6 且防火墙未拦入站时，旧行为会把共享目录暴露到互联网；私网设备仍零配置直连；
  • 共享目录选择：set_share_dir_cmd 先 canonicalize 再判断家目录/祖先/文件系统根，..、指向家目录的符号链接、Windows 大小写/8.3 短名不能绕过高风险目录二次确认；切换目录会清空所有分享票据；
  • 访问令牌（可选）：开启后非本机的 API/WS 请求必须携带 ?pin= 或 X-Access-Pin；6 位数字码（时间纳秒^进程id^自增序号经 splitmix64 扩散），状态落盘重启不静默失效；导航请求（Accept 含 text/html）回可输入配对码的 HTML 中转页而非裸 JSON；
  • 防爆破退避（v1.1.4，双层化于安全加固）：只统计「实际提交了配对码」的尝试（无码的后台轮询不计额度）；单 IP 层：连续失败 8 次后指数退避（15s 起步每次翻倍、封顶 1h）；IPv6 /64 聚合层：隐私扩展轮换接口地址刷新不了聚合窗口（40 次/60s 起步，封顶 10 分钟）——任一层处于锁定窗内一律 429，正确码也拒绝（若放行，对/错码响应可区分，攻击者伪造 Accept 头即可全速逐个试码，退避形同虚设）；锁定中不记数不延长（轰炸无法续窗），配对成功两层立即清零；逐键计数使攻击者只能锁住自己的源地址/网段。导航请求在锁定窗内回可重试的 429 表单页；配对码比较为常量时间（无逐字符短路时序差）；
  • CSP：生产 WebView 配置 script-src 'self'、object-src 'none'、base-uri 'self'；connect-src 放行 http: ws:，img-src/media-src 放行 http: 与 blob:，frame-src 放行 http:（不再 'none'）——应用内预览需要从局域网地址加载图片/音视频/PDF，只留回环会把发版包整端拦死；html/svg/xml 仍由服务端 inline 白名单挡在同源执行之外；
  • 日志卫生：日志行剥 CR/LF 防伪造注入、单行硬截断 400 字符；查询串中的 pin 一律脱敏为 pin=***。

  1. 注册单实例插件（最先）→ notification / dialog → 桌面条件注册 autostart（参数 ["--hidden"]）→ 全部命令（generate_handler!）；
  2. 构建托盘与菜单/左键点击事件；
  3. 主窗口绑定关闭事件；桌面壳窗口默认隐藏（visible(!cfg!(desktop))：桌面 false 防自启闪窗，移动壳没有托盘/隐藏→显示路径，必须初始可见否则整个 App 空白），启动参数不含 --hidden 时等前端挂载完成发 main://ready 再 show（Rust 注册 Listener + 2s 兜底：前端异常宁可空壳也不让窗口永不可见；webview 加载本不依赖 show，隐藏窗照常跑页）——消灭「空壳先出、内容后蹦」的断层，实测启动≈0.4s 即**带内容上屏**（服务就绪≈0.3s 更早）；开机自启（--hidden）不监听不兜底，收进托盘不弹；MAIN_SHOWN 与托盘唤窗共享，2s 内唤窗后再收托盘不会被兜底重新弹出；单实例回调早于建窗时短轮询补发唤窗，不再"双击图标没反应"；
  4. server::autostart() 在工作线程中自动拉起服务（共享目录在休眠外接盘/不可达 SMB 时扫描可能阻塞数秒，放 setup 主线程会拖住首帧），端口被占自动顺延，结果打 stderr：[wft] 服务已启动: http://ip:port。
  5. 端口绑定：开放局域网用双栈 [::] 并自检 v4 连通后采用，无 IPv6 / bindv6only=1 时回落 0.0.0.0（bind_dualstack，此前该回落只存在于未编译的测试代码，禁 IPv6 主机整机起不来、v4 设备全拒连）；STOPPING + STOP_IN_FLIGHT 与共享生命周期锁让 start 等在途 stop 收尾（并发第二个 stop 不会提前清标志），停启竞态不再把地址顺延漂移；停服时先广播 ws_kick 让在途上传立即回滚, 并等待 active_uploads 清空(≤3s)后才允许 start 绑定新端口——axum 连接任务是独立 spawn 的, 只 abort serve future 不会停掉它们, 否则启动清理会删掉旧 handler 仍在写的文件；启动清理顺序：先 clean_incomplete_uploads（.ccup 标记→半截成品）再 clean_stale_parts（过期断点）；两段遍历受 1.5s/2 万条预算与 32 层深度上限保护，避免 setup 线程被大目录阻塞。标记首行必须是 `ccflash-v1:` + 16 位十六进制令牌才处理——名为 .ccup 的空基名文件与用户自己的 .x.ccup 文件绝不误删；令牌下第二行声明大小与成品大小吻合 = 崩溃在"写完但标记未删"窗口，保留成品只删标记。

8.3 桌面悬浮码窗口（qr-pet）

  • 窗口：setup 内代码创建（WebviewWindowBuilder "qr-pet"，URL index.html?view=qr-pet）——无边框 + transparent + shadow(false)（macOS 会按透明窗口的内容 alpha 投影——收拢态内容是圆环，系统阴影就投成一个偏下的大灰环叠在下方窗口上，像"多出一个透明圆环"；窗口自身像素无灰环、屏幕合成才有，screencapture -l 对比即可定位。设计本意零投影，展开卡立体感由 CSS box-shadow 承担）+ always_on_top + skip_taskbar + accept_first_mouse（悬浮窗几乎总是非焦点态，macOS 首点默认只激活窗口不进 webview，不开穿透则拖动/点按/悬停全部失灵）；初始 inner_size/min_inner_size = 96×96（= 收拢态窗口，64 圆点 + 四周 16px 缓冲命中区），初始位置 = 主工作区左缘、窗口中心压边缘线（圆点漏一半）——仅是创建占位：前端首次落位成功前不 show()（petPlaced Promise + 2.5s 兜底放行），按 pet-dock 记忆（含显示器锚，见 9.12）落位后才显示，不会在主屏默认位闪现；

  • 能力：capabilities/default.json 为 main/qr-pet 两窗授予窗口几何全集（set/outer-size/position、scale-factor、current-monitor、start-dragging）+ core:window:allow-cursor-position（悬停在场轮询用）+ 事件 listen/emit；自定义 command 不走能力清单；

9.4 上传实现（整文件直传 + 锁屏保活 + 整目录）

  • 单请求整文件直传：一个文件 = 一个 XHR POST（xhr.send(file)，Blob 由浏览器流式读取、零内存整载）。整文件即"最大的分片"，无分片/账本/断点状态。代价：传输中断无断点可续（服务端删半截文件，重传 = 整份重来）；
  • XHR 替代 fetch：fetch 无上传进度事件；XHR upload.onprogress 提供实时百分比与速率展示；401/429（配对码）置 needPin 唤起配对弹框；200 响应的 final 字段与原名不同 → toast「已存为 xxx」（服务端同名自动改名）；
  • 并发闸：客户端同时最多 3 个文件在传（UPLOAD_CONCURRENCY，整文件版一个文件=一条连接），其余真实排队（waiting 状态生效）——WebKit 每 host 仅 6 条 HTTP/1.1 连接，WS/轮询/下载要留预算，一次选数百文件不再全部压上；纯内存排队，完成（成功/失败/取消，含 onabort）即出队；服务端另有 16 槽上传闸，超限直接 429（多客户端并发时保护 fd/磁盘）；
  • 锁屏保活：有上传进行中即申请屏幕常亮（v1.1.7，iOS 锁屏/熄屏会冻结上传连接 = 此前"传一半失败"主因）——Wake Lock API（安全上下文）+ 2px 静音内联视频循环（HTTP 非安全上下文的 iOS 通路；captureStream 在微信 WebView 可能抛错，先局部构造全部成功才落全局，失败可重试）；开始/完成/失败/取消各节点同步申请/释放；
  • 取消：✕ 直接 xhr.abort()，服务端连接断开路径自动删除半截文件，无需额外请求；
  • 整目录：拖拽走 webkitGetAsEntry 递归收集（混合拖入兼容、空文件夹给提示），「选择文件夹」走 webkitdirectory（iOS/iPadOS 无此能力入口隐藏），相对路径经 webkitRelativePath 保留；
  • 下载：桌面/移动壳一律 HEAD 预检（8s 超时）+ 锚点原生流式下载（壳内由 on_download 落盘系统下载目录 + 事件提示，文件名三道防线防路径逃逸）；手机浏览器 ≤50MB 走 blob（有完成时机），>50MB 原生；HTTP 错误如实报错；微信内打开顶部常驻引导条（下载被拦 → 在浏览器打开）；
  • 完成侧合并节流：非手动 loadFiles 800ms 内合并（批量上传完成风暴不再数百次串行全量拉取）；files:changed WS 事件同享该节流。

9.12 悬浮码（qr-pet 窗）实现

  • 几何模型：petDockPos(edge, cross, w, h, wa, collapsed)——收拢 inset=0.5（窗口中心压边缘线，圆点漏一半），展开 inset=0（完整贴边）；跨轴夹紧在工作区内；展开顺序先就位再放大（原点固定向屏内生长）、收拢先缩球再滑入半隐，过渡期间永不露出屏外；macOS 会把顶边钳到菜单栏下沿（constrainFrameRect，横向/底部越界则放行）——顶吸附表现为完整贴边，属系统行为；
  • 单飞串行：petSerialize() 把 展开/收拢/吸附/锁屏重试落位 全部排队执行——并发交错 setSize/setPosition 会产生"136 卡片配 96 收拢位姿"错配（诊断 pref-pet-dbg-apply 实锤过 y=-70 半出血）；执行瞬间从 ref 推导尺寸与位姿（同源），snap 则按窗口实际尺寸推导（96→半隐 / 136→贴边）自洽自纠；
  • 多屏 / 扩展屏：petWorkArea(preferDock) 双模式解析工作区——落位（启动恢复/展开/自愈）走 preferDock=true，先按 dock 记忆的显示器锚 mon={name,x,y} 找目标屏（petFindMonitor：同名多屏按原点就近，系统改名退化按原点匹配），不这样会按窗口当前所在的主屏解析、重启后从扩展屏跳回主屏；吸附走 preferDock=false 用窗口当前所在屏（拖到哪块屏吸哪块屏），松手后把锚迁到该屏。记忆屏离线时退当前屏并标 viaFallback——不回写 cross/mon（保持原锚），heal 30s 巡检发现 petWaFallback && 记忆屏回归（monBack）即主动归位，窗口中心越出工作区 ±16px 同样触发重落位；兜底态下落位幂等、不会巡检风暴；
  • 跨屏 API 语义（两个实测根因）：① 选屏必须用模块级 currentMonitor()（@tauri-apps/api/window，经 plugin:window|current_monitor 注入调用方窗口）——WebviewWindow 实例上没有该方法，win.currentMonitor() 抛 TypeError 被 catch 静默吞掉，v1.1.9 起吸附一直退化为 availableMonitors()[0]＝永远主屏（球拖到扩展屏会被吸回主屏的根因）；拿不到时按"窗口中心落在哪块屏"几何选屏兜底（全部换算到逻辑点比较，混 DPI 安全）。② 在场轮询的坐标空间：macOS 上 cursorPosition raw = 全局逻辑点 × 主屏 sf（tao util::cursor_position 固定乘 primary_monitor().scale_factor()），outerPosition raw = 逻辑点 × 本屏 sf——混 DPI 必须各自除回逻辑点再比较（否则球在扩展屏 sf1、主屏 sf2 时，光标值翻倍、悬停永不触发）；Windows 三者都是真实物理像素，必须同空间直接比较，"÷主屏 sf"只在 macOS 成立（主屏 100% + 扩展屏 150% 时 Windows 悬停必挂）；primaryMonitor() 需要 core:window:allow-primary-monitor 权限（能力清单已补），缺失时退化为原点 (0,0) 屏的 sf；
  • Windows 混合 DPI 落位：tao 把 LogicalPosition/LogicalSize 按窗口当前所在屏的缩放换算——目标屏(记忆屏/扩展屏)与当前屏缩放不同时球会落错位并永久出屏，heal 每 30s 用同一错误公式重算成死循环。Windows 下改用 PhysicalPosition/PhysicalSize（逻辑位姿 × 目标屏 sf），macOS/Linux 保持 Logical（全局坐标系本就是逻辑点）；
  • 就绪门控与休眠：Pet 完成首次落位（或 2.5s 兜底）后调 pet_ready_cmd，Rust 的 PET_READY 未置位前 show_qr_pet_cmd(true) 一律拒绝——主窗 2.5s 状态轮询的"兜底重显"不会再抢在落位前把窗口 show 到主屏默认位；离开事件在几何态或展示态任一展开时都会排收起（展开落位未完成时只看 qrPetShown 会吞掉 leave，窗口卡在展开态）；悬浮码关闭后 Pet 窗停止 WS/聊天/文件轮询，重新开启再恢复；
  • 悬停判定：权威通道是 250ms 光标轮询（cursorPosition() ∩ 窗口 outer 矩形 → petSetOver 穿越边界才动作）；mouseenter/leave 只作加速通道。原因：mouseenter 是边界过渡事件，窗口被程序化移动（贴边落位）或页面重载后 WebKit 会丢失进出配对（认为指针一直在窗内 → enter 永不再发），实测"点击正常、悬停永不触发"；

  • 发布保护：产物 find ! -name "*unsigned*" ! -name "*-debug*" 兜底；Android 上传前用 gh release view --json isDraft 校验 Release 仍为草稿——重跑已发布 tag 时 desktop 腿必失败，但 android 腿（always）原本会把新 APK 写进线上 Release，绕过"全绿才发布"；desktop job 失败时 APK 仍可写入草稿，但 Release 保持草稿，人工确认后手动 Publish；
  • 一键发版：./scripts/release.sh X.Y.Z|X.Y.Z.W [提交信息]——升版本（四段 tag 的应用版本取前三段）/同步兜底版本与 Android versionCode/提交/打标签/推送（3 次重试 + GitHub API 建 tag 引用兜底，应对 git 443 通道抖动），并轮询验证 Actions 已触发；脚本对暂存区做扩展名+内容双私钥扫描，并打印暂存/未跟踪清单，避免"一锅端"夹带；workflow 改动必须经 release.sh 提交进 tag，手打 tag 会用旧版工作流构建；

  • 注意：git 推送标签与 main 同批推送存在事件偶发丢失的情况，脚本采用分步推送 + 触发验证来规避。
