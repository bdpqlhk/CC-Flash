一、后端安全与数据完整性

问题修复
Windows 可用 foo.、foo 、foo::$DATA、8.3 短名等别名绕过 active_uploads 与 .{名}.ccup 标记；慢速上传期间删掉标记后，半截文件会以完整文件出现在列表并可 200 下载。safe_rel_path 读路径在 Windows 拒绝段内冒号/尾随点/尾随空格；delete_file 新增 canonical_rel_name，从 canonical 真实路径反推相对名，active key、marker、system .ccup 判定全部基于真实名。8.3 短名同样被 canonical 归一。
上传在 async handler 里同步 exists()、读 marker，upload_cancel 持锁做同步文件操作；共享目录在 NFS/SMB/休眠盘时 16 个并发上传即可阻塞 tokio worker。目录探测改 tokio::fs::metadata；marker 读取与 upload_cancel 的 metadata/remove_file 移入 spawn_blocking；仍保留占位→标记→在途登记的临界区语义。
缺失/损坏 X-File-Size 时按“未知大小”接收，干净结束的截断体回 200。同时读取 X-File-Size 与 Content-Length；不一致 400，都缺失 411；声明大小为硬上限，末尾仍校验 written == size。
PIN 用时间/pid/序号生成；桌面端 NotFound 被当作“从未开启”，网络 home 未挂载/文件被清理时保护静默消失；移动端关闭令牌重启后又自动复活。new_pin 改用 fill_random CSPRNG；新增 .ccflash-pin-enabled 独立标记与 install_pin/write_pin_enabled；读取时区分“从未开启 / 明确关闭 / 开启但码值丢失 / 读取失败”，后两者 fail-closed 重新生成；关闭时先写 0 再删码值，重启不复活。
缩略图/预览把长期 PIN 拼进 <img>/<video>/<iframe> URL；分享/下载已用一次性票据，两套口径不一致。新增 /api/media-session：10min、绑定来源 IP、可重复 HEAD/GET/Range；前端 ensureMediaToken 单飞去重，thumbSrcs/authedPreviewUrl 共用；令牌过期/IP 变化时 @error 重开；分享链接仍为一次性票据。
成功下载/上传/删除的 handler 日志无准入，普通请求可刷满 2000 条审计环，把 PIN 锁定等事件挤掉。push_log_lvl 为 WARN 预留 200 条；成功下载/上传/删除日志过 log_admit；普通 INFO/OK 最多占 1800 条。
普通用户 *.ccpart 文件被列表隐藏，带 16hex 的旧断点 7 天后可能被静默删除。is_part_artifact(path,fname) 只把能对上会话 meta 指纹的断点视为内部产物；普通 .ccpart 可见、不会被清理；clean_stale_parts 额外校验 meta 首行 id 的 FNV 指纹。
UDP bye 可被同网段伪造，驱逐真实设备。announce 携带每进程 tok，bye 必须回带同一令牌；DeviceInfo.token 不序列化。发现协议仍无强身份认证，假 announce 风险作为已知边界保留。
Range 后缀区间 bytes=-N 被忽略，播放器读取文件尾部时退化成 200 全量。解析后缀区间为末尾 N 字节；0 字节/0 后缀返回 416；保留单区间、If-Range、take 截断。
下载可通过精确文件名取到 .DS_Store、系统 .ccup、会话断点等列表隐藏文件。download 在 canonical 基名上拒绝系统垃圾/内部产物；用户自建 .ccup 仍允许。

二、前端与多端交互

  • 手机 App 四页宽屏修复：filePanelIsSheet() = isNarrow || mobileTabbed，FILES 页不再依赖 980px 断点；.tx-files.sheet:not(.open){display:none}；平板/折叠屏横屏可正常打开，旋转后 onMqChange 不再把 DEVICES/FILES 弹回 SEND；DEVICES 与 FILES 互斥。
  • FILES 页上传归属：文件页“上传文件 / 拖入 / 粘贴文件”固定走本机共享，不再沿用发送页残留的直发目标；文件页头部标注“本机共享”。
  • 发送面板层级：z-index 1100 → 1006，低于配对码弹框（1008）与 toast（1010）；401/离线时错误可见、可输入对方配对码；移动端用 --app-vh/--app-vv-top，输入字号 16px，iOS 文件夹入口给出明确提示。
  • 批量直发重试：directSendFiles 返回 {allOk,sent}；部分失败时只保留未成功文件，重试不再重复发送已成功项。
  • 未读语义：新增 chatCovered，DEVICES/FILES/发送面板/预览/配对/删除/昵称/历史/诊断/二维码等覆盖聊天时不标记已读；首拉与断网恢复也走 markChatSeen。
  • 剪贴板口径：自动同步只在本机服务的共享槽与打开该地址的浏览器/客户端之间生效；电脑 App 与手机 App 不自动互通，跨 App 使用发送面板「剪贴板」投递。显式“粘贴”按钮也会 publishSharedClip，不再只填输入框。
  • 文本预览：文本先 HEAD 拿 Content-Length（列表没有 meta 也能拦住 >2MB），超过 2MB 提示下载；预览地址统一票据。
  • 昵称与监听器：昵称统一按服务端 20 字符截断，避免自己的消息被误判为他人；补齐 contextmenu/click/scroll/resize 监听器的卸载。
  • 系统设置入口：open_url_cmd 严格放行 x-apple.systempreferences: 与 ms-settings:（Windows 走 rundll32），诊断页“打开网络设置”不再必然失败。
