五、v1.2.9.1 发布后的二次全量审查修复

在 v1.2.9.1 发布后，对本地最新完整代码做了一轮只读全量审查（前端 / Rust 服务端 / Tauri 配置 / Android 壳 / CI 发版链路），随后按审查清单逐项修复。未发新版本、未改版本号。

5.1 安全与发现

  • 发现 id 增加持久化 TOFU 绑定（peer-bindings.json）：在线期间同 id 从新 IP 宣告拒绝；10 分钟无宣告才允许 DHCP/重启迁移；空令牌不能覆盖已有令牌；空令牌 bye 不再删除条目。
  • peer-cache 写盘改为 5 秒合并，设备在线态广播统一 1 秒节流，限流表清理改为每秒最多一次；避免伪造源轮换造成每包 fsync / 全表广播 / O(n) 扫描。
  • WS 全局 64 + 单来源 8；文件列表全局 2 + 单来源 1；断点查询/取消/幂等查询共享 8 个全局许可；body 闸按 IPv6 /64 聚合。
  • 上传 60 秒增量低于 128KB 即中止（原 16KB）；下载保留 45 秒无进展与 2 小时总时长看门狗。

5.2 数据完整性与持久化

  • file-history.json 损坏时改名保留 .bad-*，不再静默清空；聊天/文件/剪贴板写盘失败写 ERROR 日志。
  • Windows write_secret_atomic 回落改为“旧文件先改名 .bak → 替换 → 成功删除 / 失败回滚”，不再先删唯一副本。
  • 悬浮球导入在 FAT/exFAT/SMB 的硬链接回落改为 create_new + 复制，避免 check-then-rename 覆盖并发同名文件。

5.3 幂等与传输体验

  • 聊天新增 clientId 服务端去重；上传新增 X-Upload-Id 与 /api/upload_status；上传行重试命中完成记录时直接恢复，不再生成 xxx(1)；直发文件重试先查对端完成状态。
  • 多选直发文本：全部成功才清空；部分失败保留草稿，并把未成功目标保留为选中，重发只发失败目标；直发文本补引用。
  • 多选直发文件：单台失败不阻断后续目标；400/413/500/507 解析服务端原因并汇总“成功 N / 失败 M”；不再统一误报“无法连接设备”。
  • 剪贴板所有发布入口统一受自动同步开关约束；桌面共享文件抽屉内拖拽固定上传本机；手动发送面板拖拽支持文件夹递归；失败/取消上传行不再屏蔽同名远端卡片。
  • 悬浮球一次拖入多文件部分失败时返回 files/errors，前端显示“已上传 N，失败 M”，重试不再重复已成功文件。

5.4 平台与发版
