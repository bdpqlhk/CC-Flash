01
DECISION

采纳微信式结构，统一到一条时间线。

这不是“给四端各做一套”，而是一套产品、四种外壳。对话时间线、文件卡片、共享文件抽屉、 ＋面板与输入栏是共同区块；桌面壳多一个侧栏、托盘与悬浮码，浏览器多一个地址与标题， 手机多一层键盘与安全区，手机 App 多一个"本机节点 / 连接电脑"的模式切换（默认本机安全模式）。

SHARED CORE

一套对话结构

消息气泡、文件卡片、文件组、上传总览、共享文件抽屉、＋面板、输入栏。四端复用，不在各端重画。

结构一致，只按容器宽度缩放
PLATFORM SHELLS

四种外壳

桌面壳 = 侧栏 + 应用窗口；电脑浏览器 = 标签页 + 顶部栏；手机浏览器 = 地址栏 + 页面； 手机 App = 状态栏 + 客户端门。

外壳不同，时间线相同
ZERO REGRESSION

功能只换位置

上传、下载、排序、分页、批量删除、分享、聊天、未读、访问令牌、票据、悬浮码、托盘、自启全部保留。

详见第 08 节能力矩阵
02
INFORMATION ARCHITECTURE

一个入口「消息发送」，四种到达方式。

旧的「文件传输 / 文本消息」两个导航项合并为「消息发送」。文件管理从独立页面变为桌面右侧抽屉 / 移动底部面板； 聊天、远端文件与本次上传共享同一条时间线。服务中心与 CC设置保持原职责（移动壳不显示服务中心）。

BEFORE

两个页面，两套注意力

文件页负责列表与上传，聊天页负责消息；手机上还要在文件页与悬浮球面板之间切换。

文件 / 消息两个入口 · 手机多一个悬浮球
AFTER

一条时间线，一个抽屉

上传成为文件卡片，文字仍是气泡；共享文件抽屉 / 面板负责长期管理。侧栏只剩「消息发送 / 服务中心 / CC设置」。

未读只出现一次 · 文件管理不消失
UNREAD

消息计未读，文件点绿点

聊天消息进入未读计数；新文件只在共享文件按钮上点绿点，不把“3 个文件”混成“3 条消息”。滚到底部也会立即追平未读。

03

微信式结构，CC 的皮肤。

没有壳能力，但有地址

浏览器不显示托盘、悬浮码、服务启停与日志面板；它只负责“访问这台电脑的服务”。房间头保留复制地址、二维码与共享文件入口，共享文件抽屉宽 340–400px，可收起。

标签标题就是未读

有新消息且页面不在前台时，把未读数写进标签标题（(3) CC Flash · 消息发送），并在房间头「共享文件」旁显示角标；页面可见 + 窗口聚焦时清零，滚到底也追平。

下载交给浏览器

点击文件卡或抽屉行 → 先 HEAD 预检，再交浏览器原生下载（带进度、断点续传）；手机浏览器 ≤50MB 走 fetch + blob，超过 50MB 走原生流式，避免 iOS 内存配额杀标签页。

窄窗口退化为手机形态

窗口宽度 <980 时，抽屉变为底部共享文件面板：房间头 + 单列时间线 + 86dvh 面板，与手机浏览器同一套布局。

应用内预览

浏览器与移动端：图片 / PDF / 纯文本 / 音视频打开应用内全屏层，右上角关闭或 Esc 返回；办公文档 / 压缩包下载；html / svg / xml 不内联。真实桌面沿用系统程序打开；PDF 在桌面 / 移动壳交系统浏览器。

Markdown 与主题

聊天支持标题 / 列表 / 引用 / 代码块 / 行内代码 / 链接；多行输入框自动长高。5 套配色 × 亮 / 暗 / 跟随系统，桌面气泡跟随主题。

下载策略

≤50MB 走 fetch + blob（有完成提示）；>50MB 交浏览器原生下载（省内存、带进度）；HTTP 错误如实提示，不把 JSON 错误体当文件。

微信内置浏览器

顶部引导条只在微信内置浏览器出现（点 ⋯ → 在浏览器打开），≤980px 只占一行、不再占满整屏；下载被拦时复制链接兜底；分享链接带一次性票据（10 分钟、单文件、下载一次即失效）。

键盘与安全区

输入栏使用 dvh / visualViewport 与 env(safe-area-inset-bottom)；键盘弹起时保持输入框可见，消息列表自动贴底。多行输入框 16px，避免 iOS 聚焦缩放。

无连接门

能打开页面就说明地址可达。服务停止 → 整页「无信号」；地址变化 → 用电脑端新地址重开。

FIRST RUN / LOCAL NODE

首次打开：本机安全模式

App 自动拉起本机服务并连 127.0.0.1，无需输入电脑地址；网关页失败可点「重新启动本机服务」。只监听回环，同 Wi-Fi 设备访问不到。

DUAL MODE

本机节点 / 连接电脑

CC设置 → 本机服务 可开启「局域网访问」、访问令牌并重启服务；也可填电脑地址切到「连接电脑」浏览电脑共享文件，随时「切回本机节点」。下载通过系统浏览器打开，失败复制链接。

NO SIGNAL / RESET

失联：自动重探或切回本机

连本机时服务重启换端口会自动重新探测；连电脑模式下无信号页点「重新启动本机服务」回到本机节点，也可在 CC设置 → 连接电脑 改地址。

重新启动本机服务

Android

提供按 ABI 分包的 release 签名 APK；返回键先关＋面板 / 文件面板，再退到系统；通知与下载交给系统。

iOS

当前不提供安装包；iOS 用户用 Safari 打开电脑地址使用网页版。本地网络权限与壳能力尚未适配。

设置页

只保留「连接电脑」、皮肤、关于与检查更新提示；不展示开机自启、悬浮码、服务启停等桌面能力。

安全区

输入栏与底部面板处理 safe-area-inset-bottom；键盘弹起时＋面板与键盘互斥，切后台回来保留滚动位置。

跨端规则约定
文件卡片完成态在四端都有「打开 / 下载 / 分享 / 定位」中的适用动作；移动端用「⋯」动作面板，不依赖长按。
文件组一次 >3 个或 60s 内连续上传合并；展开后单项仍可取消 / 重试；抽屉始终是完整列表。
历史文件只把本次会话真实发生的上传当消息；刷新后历史文件回到抽屉，不伪造时间与发送者。
服务状态停止：输入栏上方一条内联提示 + 上传/发送禁用；失联：整页「无信号」；手机端额外给「重新设置地址」。

安全Host 仅 IP / localhost；6 位 PIN 配对（本机豁免，按 IP 退避 + 公网全局预算）；分享一次性票据（10 分钟、单文件、一次、绑定 ETag）；客户端上传并发 3、服务端上传 16 / 下载 32；CSP 放行 media-src http: blob:；控制接口拒绝跨站；手机端默认安全模式（仅 127.0.0.1），需在 CC设置 开启局域网访问。
可访问性焦点环、键盘顺序、触屏无 hover 时动作常显、reduced-motion 四端一致。

IMPLEMENTATION

一套结构，四种外壳。

当前 v1.2.1 仍在 App.vue 内以区块 + 同一套 CSS 变量实现四端复用，尚未拆成独立组件文件； 下图的组件树是结构示意。不重写服务端、不重写上传/聊天底层；只新增时间线与平台外壳。

// 共享页面：四端都用它 TransferPage ├─ RoomHeader // 房间 / 运行状态 / 共享文件入口 ├─ ChatTimeline // 消息 + 文件卡片 + 文件组 ├─ UploadStrip // 在途上传总览（可点击定位） ├─ Composer // 文字 + ＋ 面板 └─ FileManager // 桌面抽屉 / 移动面板 // 四种外壳只决定容器 ShellLayout = Topbar + Sidebar + TransferPage + Drawer + 托盘/悬浮码 WebLayout = RoomHeader + TransferPage + Drawer MobileLayout = RoomHeader + TransferPage + Sheet MobileAppLayout= StateBar + ConnectGate? + MobileLayout // 时间线（仅本次会话的上传） const timeline = ref([]); const merged = computed(() => sortByTime([ ...chatMsgs.value.map(m => ({ type: "msg", ...m })), ...timeline.value, // file / filegroup ]));

1共享区块

把现有聊天、文件列表、上传条目按 ChatTimeline / FileManager / Composer 的职责组织；当前仍在 App.vue 内，未拆独立组件文件。

2时间线主干

新增 timeline，上传 start/progress/done/fail 生成或更新文件卡片；聊天消息按时间戳并入。

3四端外壳

桌面壳侧栏 + 340–400px 抽屉；电脑浏览器房间头 + 抽屉；手机浏览器 / App 单列 + 86dvh 面板；App 首次连接门。

4文件组与抽屉

批量上传合并；抽屉 / 面板复用现有 allFiles、排序、分页、选中与批量删除；分页占满底栏，新文件绿点。

5平台差异

桌面壳保留托盘/悬浮码与跟随主题的气泡；浏览器加标签标题未读；手机 App 加连接门与系统下载；预览层浏览器 / 移动端共用，真实桌面走系统程序，PDF 在壳内交系统浏览器。

6回归验收

按第 10 节四端矩阵跑上传、下载、聊天、未读、停服、失联、令牌、断点。

改动风险与规避
  • 时间线刷屏：文件组必须做；一次 200 个文件不能把聊天记录淹没。
  • 历史与刷新：时间线只保留本次会话真实发生的上传；刷新后历史回到抽屉，不伪造。
  • 移动端键盘：输入栏与＋面板、文件面板、键盘三者的层级要明确；键盘弹起先收面板。
  • 浏览器标题：未读写入 document.title 后，离开页面要恢复原标题；注意与其他页面标题的冲突。
  • 桌面壳布局：窗口 <980 时切换到单列 + 底部面板，但托盘 / 服务能力仍在；不要误删桌面专属入口。
  • 预览与 Range：音视频 / PDF 会发多次 Range，一次性票据首个 206 即失效；应用内预览改用长期 PIN 直连，且不写进浏览器历史。
  • 内联安全：html / svg / xml 不得 inline 打开；服务端 is_inline_safe 与 CSP 必须同时兜底。
