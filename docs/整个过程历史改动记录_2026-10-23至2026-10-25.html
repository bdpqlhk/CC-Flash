项目：CC-Flash（局域网文件互传，Tauri 2 + Vue3 + axum） 记录范围：2026-10-23 ~ 2026-10-25（另含背景溯源） 依据：git 历史 + 开发会话记录 + 需求/技术文档 + 代码现状

一项目背景与重构决策（v1.0.0 之前）

1.1 前身

Python / PyQt6 版局域网文件互传工具（v2 线，lan-file-transfer-v2），验证了完整的产品形态：电脑启动服务 → 手机浏览器扫码访问 → 上传/下载/分享/聊天。

1.2 为什么用 Tauri 重写

维度PyQt6 旧版Tauri 新版（本线）
安装包体积约 56 MBdmg 5.9 MB / .app 13.5 MB ✅
技术栈Python + PyQt6（桌面 UI 即网页的替代）Rust(axum) 后端 + Vue3 前端 + Tauri 2 壳
网页端独立 webui 模块与桌面端同一份 Vue 页面，按运行环境自适应双形态
协议兼容—与 Python 版 API 协议完全一致，老用户零迁移成本

1.3 产品原则

  • 零配置：安装即用，端口/目录全自动，端口被占自动顺延；
  • 零学习成本：文案口语化（"保姆级"标准）；
  • 可信赖的反馈：每个动作都有 toast，服务状态常驻可见（三圆点脉冲徽标）；
  • 低刺激视觉：全局深色主题，5 套可切换皮肤，颜色语义化（蓝=主操作、绿=成功/分享、红=危险）。

四停服体验修复系列（10-24）

背景：服务停止后，已打开的浏览器页面表现混乱——状态仍显示"运行中"、残留旧数据、删除报"成功 0 个失败 N 个"。共 7 项修复：

类型改动说明
修复 状态显示回落 refreshStatus() 判定失联时 running 残留为 true → 现同时置 false，状态胶囊立即变"○ 已停止 / HTTP 服务未启动"。根因：失联只置了 offline 弹横幅，没动 running。
修复 删除前拦截 新增 offlineGuard()：单个删除、批量删除、doDelete 兜底三处先判断，直接提示"服务已停止，无法删除"，不再发出必败请求。
修复 失联清空数据 失联时清空 allFiles（列表回落空状态）、聊天消息、未读徽标、勾选项，不再展示停服前残留；服务恢复后轮询自动重新拉取。
功能 失联全屏"无信号"测试卡 替代原黄色横幅：nosignal-overlay 全屏遮罩（测试卡图 + 📡无信号 + 断连原因 + 重开指引），电脑/手机浏览器表现一致，桌面 App 不受影响。踩坑修复：图片起初放 public/ 靠运行时请求，失联那一刻必然 404 → 移入 src/assets/ + vite assetsInlineLimit 200KB 内联 base64，断网前就在页面内存里。
修复 桌面端同步删除拦截 桌面端删除同样走 127.0.0.1:端口 回环请求，停服后同病 → 抽出 serviceDown()（桌面看 running / 网页看 offline）双端统一判断。
修复 失联判定提速 10s → 5s 状态轮询间隔 5s → 2.5s，保留"连续 2 次失败"双确认防误判；服务恢复检测同步提速。代价仅每页每秒半个小 JSON 请求。
修复 分享/复制链接拦截 停服后点分享不再复制打不开的链接（"服务已停止，无法分享"）；顶栏"复制链接"统一走 serviceDown()。

五配置化重构（10-25，方案 A / C / B / D）

背景：深度盘点出 40+ 处散落的魔法数字/字符串（轮询间隔、端口范围、长度限制、API 路径、存储键、话术、白名单……），且存在前后端双写、注释漂移（日志白名单注释还写着"5s 一次"）等实际问题。

A：前端配置中心 src/config.js

  • 轮询/时序 ×11、分页大小、1GB 原生下载阈值、窄屏断点、昵称/消息上限、默认端口、API 路径表、localStorage 键表、相对时间阈值、图标映射表（60+ 扩展名）、头像池、默认昵称、3 条话术模板、页脚文案。
  • App.vue 约 30 处替换；main.js 主题键统一（"wft-theme" 原本双写两处）。

C：Rust 配置中心 src-tauri/src/config.rs

  • 应用名、默认端口 + 顺延窗口、聊天保留条数/昵称/消息/预览截断、日志上限、下载流缓冲、共享目录名/旧名/持久化文件名。
  • 日志噪音白名单数组化：NOISY_GET_PATHS 常量数组替代字符串堆叠，漂移注释改为指向 config.rs。
  • 托盘 tooltip、系统通知标题改用 APP_NAME。

B：/api/info 下发配置，消灭双写

  • config.rs 成为唯一事实源；frontend_config() 随三个出口下发：/api/info、/api/control/status、桌面 invoke control_status_cmd：
{ "ip": "...", "port": 1688, "running": true,
  "version": "1.1.1",
  "config": { "nickMax": 20, "msgMax": 2000, "defaultNick": "匿名用户",
              "chatMax": 200, "poll": { "chat": 3000, "files": 5000, "status": 2500, "logs": 2000 } } }
  • 前端响应式 cfg 对象：config.js 值仅作启动兜底，服务端下发后（带合法性校验）覆盖；轮询间隔变化时 startPolling() 自动重排定时器。改 Rust 一处 + 重启服务，所有网页端自动跟随，无需重新构建前端。
  • 跨端约定项以 [同步: config.rs xxx] / [同步: config.js xxx] 注释互相指向。

D：版本号单一来源

  • 唯一来源：Cargo.toml 的 [package] version；tauri.conf.json 删除 version 字段（Tauri 自动回退读 Cargo.toml）；APP_VERSION = env!("CARGO_PKG_VERSION") 编译期取同源值随接口下发；侧边栏 "v1.0.0 · Tauri" 硬编码删除改为动态显示。发版只改一处。

六CI 三平台发版攻坚（10-25，六轮修复 + 两次补刀）

背景：首次启用 GitHub Actions 三平台自动构建（推送 v* 标签触发）。macOS/Windows 桌面链路较快跑通，Android 为项目首次移动端编译，连续暴露六类问题；全部修复后 v1.1.0 / v1.1.1 双 Release 五资产就位。

轮现象根因 → 修复
1Release 创建被拒（Resource not accessible by integration），desktop 双 job 构建成功却上传失败GITHUB_TOKEN 自 2023 起新仓库默认只读 → workflow 声明 permissions: contents: write。
2Android：sh: 1: tauri: not found（exit 127）android init 步骤排在 npm install 之前，tauri CLI 尚未安装 → 调整步骤顺序。
3移动端编译失败：托盘/关窗 API 不存在托盘、关窗收纳、首次通知均为桌面专属 API → #[cfg(desktop)] 门控（含 import、静态量、setup 代码块）。
4移动端编译失败：E0282（lib.rs:51 setup 闭包）桌面端闭包体经 MenuItem::with_id(app,…) 为 app 提供类型约束，门控后移动端失去全部约束点 → 参数显式标注 |app: &mut tauri::App|。
5移动端编译失败：E0282（server.rs copy_file_cmd）剪贴板实现为 mac/win/其他 三分支条件编译，"其他"分支 Err(…) 的泛型 T 无约束 → 显式标注 Result<std::process::Output, std::io::Error>（Linux 同样受益）。
6APK 组装失败：.so 缺 JNI 运行时符号（库校验不通过）移动端必须由宏生成 JNI 入口 → run() 标注 #[cfg_attr(mobile, tauri::mobile_entry_point)]。
7Gradle 跑的是 Release 变体（未签名装不上手机）--debug 恰好是 npm 自有参数被吞掉未透传 → 改用 npx tauri android build --apk --debug 原样透传。
8APK 重命名失败：固定输出路径 No such file or directory输出目录系假设 → 改 find … -name "*.apk" 定位 + 带版本号重命名。

6.1 沉淀的工具与经验

  • 体积优化：debug universal APK 527MB（4 架构 × 无优化 + 全量调试符号）→ release 变体（模板默认 debug 签名，可直接安装）约 20MB；
  • 本地预检：cargo check --target aarch64-linux-android 无需 NDK 即可在 30 秒内复现移动端编译错误，替代 10 分钟一轮的 CI 试错；
  • 应急推送：scripts/api-push.sh <标签>——github.com:443 中断时经 api.github.com 走 Git Data API（blob→tree→commit→ref）完成推送并重建标签，实战验证有效；
  • 一键发版：scripts/release.sh X.Y.Z [信息]——升版本/提交/打标签/3 次重试推送/API 兜底/触发验证；
  • 经验：git 推标签与 main 同批推送存在事件偶发丢失，脚本改为分步推送 + 触发验证规避。

十遗留事项与下一步

  1. iOS 真机包：需 Apple 开发者账号（$99/年）+ 证书配成仓库 Secrets，workflow 内已备注释模板，账号到位即启用；
  2. 二期：plugin-updater 应用内自更新：后台下载 + 自动重启；前置 minisign 签名密钥 + 各平台签名产物 + latest.json 托管，建议配套 GitHub Actions；
  3. Android 正式签名：现 APK 为 debug 签名（可直接安装，适合内测分发）；上架应用市场需正式 keystore 配 Secrets；
  4. 小尾巴：前后端两份大小单位表（fmtSize / humans）可随下次改动统一；
  5. release.sh 实战检验：v1.1.1 当天因网络走的是手动 + API 混合通道，脚本逻辑已验证（版本守卫生效、API 兜底逻辑同源），下次发版走一遍完整流程。
