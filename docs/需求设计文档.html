1项目背景与目标

同一 Wi-Fi 下的多台设备（手机 / 平板 / 电脑）之间经常需要快速互传文件、传一句话/一个链接。传统方案（微信文件传输助手、AirDrop、网盘）分别存在登录负担、生态限制、速度慢的问题。本项目提供一个零登录、零公网、开箱即用的局域网传输工具：

  • 电脑上启动服务，自动生成访问地址与二维码；
  • 手机 / 平板 / 电脑用浏览器扫码即可访问，无需安装任何 App；
  • 支持文件上传 / 下载 / 删除 / 分享，以及一个轻量聊天室。

1.1 技术形态

维度形态
技术栈Rust(axum) 局域网服务 + Vue3 前端 + Tauri 2 桌面壳

网页端与桌面端同一份 Vue 页面，按运行环境自适应：桌面壳（176px 侧栏 + 消息工作台 + 文件抽屉）/ 电脑浏览器（顶部房间头 + 抽屉，原聊天室单页）/ 手机浏览器（单列原聊天室，无底部标签）/ 手机 App（「发送 / 设备 / 文件 / 设置」四页 + 文件面板）
页面托管前端产物由服务端直接托管，手机扫码即用，无独立部署步骤

1.2 产品原则

  • 零配置：安装即用，端口/目录全自动，端口被占自动顺延；
  • 零学习成本：所有操作一目了然，文案口语化（"保姆级"标准）；
  • 可信赖的反馈：每个动作都有 toast 提示（上传/下载/复制/清空/错误），服务状态常驻可见（三圆点脉冲徽标）；
  • 低刺激视觉：亮色 / 暗色 / 跟随系统三种模式 × 6 套可切换配色（信号台 / 深空蓝 / 石墨玫瑰 / 森林薄荷 / 暗夜紫 / 墨色琥珀），颜色语义化（蓝=主操作、绿=成功/分享、红=危险）。

2.1 核心场景

  1. 照片回传：手机拍的照片 → 浏览器上传 → 电脑立即取用；
  2. 资料分发：电脑把安装包/文档放进共享目录 → 同事扫码下载；
  3. 链接传递：电脑上复制的长链接 → 粘到聊天室 → 手机点开；
  4. 临时接力：开会时把会议纪要丢进聊天室，所有人立即可见可复制。

4文件共享模块

4.1 上传

  • 入口：拖拽区点击、拖放文件/文件夹（递归收集、保持目录结构）、粘贴事件（截图直接 Ctrl+V / Cmd+V）、「选择文件夹」、多选；
  • 每项展示：文件名（含子目录相对路径）、状态（等待中 / 百分比+速率 / 完成 / 失败原因）、进度条；
  • 协议：POST /api/upload，文件名（相对路径）放请求头 X-Filename（URL 编码），声明大小放 X-File-Size 或 Content-Length（必须至少一个，二者不一致 400、都缺失 411），body 为文件本体（单请求整文件直传）；
  • 服务端先做磁盘空间预检（按声明大小）；流式落盘每 64MB 复查剩余空间，不足即中止并清理半截文件（防 size=0/谎报大小灌满磁盘）；
  • 单请求整文件直传（v1.1.8 定策）：body 逐帧流式落盘、零内存占用；create_new 原子占位 + 同名自动改名 xxx(1).zip 顺延，任何场景不覆盖既有文件；Windows MAX_PATH(260) 双重预检（原名 + 改名变体）；长文件名含 .ccup 标记预检（base.len()+6 > 249 提前拒绝）；写首字节前落 .{名}.ccup 完整性标记（ccflash-v1:+会话令牌/声明大小；"ok"/空标记/用户自建文件区分处理），中断的半截文件立即清理，目录中不残留残缺文件；
  • 服务端上传并发闸 16、空闲 120s、总时长 6h、低速闸（连续 60s 增量 < 16KB）；客户端并发闸限制同时 3 个文件在传（WebKit 每 host 6 连接预算），其余排队；上传期间手机屏幕自动保持常亮防锁屏冻结；上传断点续传移入后期规划（见里程碑）。

4.2 下载与分享

  • 浏览器端：GET /api/download/*name（支持子目录路径），响应带 Content-Disposition attachment（RFC5987 支持中文）与 Content-Length（浏览器可显示进度）；服务端下载并发闸 32；断点续传：支持 Range（浏览器断下重试自动从断点继续，206/416 语义完整），10GB 文件传到 8GB 断掉不再从零重来；
  • 应用内预览：?inline=1 且类型安全（图片/PDF/文本/音视频）时返回 inline，全屏层直接查看；html/svg/xml 一律 attachment，避免在服务同源执行脚本；预览使用短时媒体会话令牌（10 分钟、IP 绑定、可重复 Range），音视频多段 Range 不会 401；
  • 分享：任何端点击「分享」= 复制下载链接到剪贴板，自动附加话术：
    固定话术（需求原文）「🔔 温馨提示：请在同一 Wi-Fi 下打开；文件请尽快下载到本地，共享文件不保证长期有效。」
  • 开启访问令牌时，分享链接自动携带一次性票据（绑定该文件、10 分钟有效、下载成功即作废）：接收方点开即可下载、无需输入配对码，且链接只能下载这一个文件；关闭令牌时链接为直连地址。票据在指针悬停到「分享」按钮时后台预取，点击时同步完成复制（不因等待签发而复制失败）；

6.2 IP 变化可靠性需求（FR-60）

服务监听双栈 [::]（v4 自检失败回落 0.0.0.0）；移动端始终开放局域网，旧版安全模式不再生效；DHCP 换 IP 不会中断服务，但客户端手里的旧地址会失联（表现为连接超时）。因此要求：

  • 前端每 2.5 秒刷新一次状态；检测到 IP 变化 → 地址栏/二维码/统计立即换新，并弹醒目提示「本机 IP 已变为 x.x.x.x，手机请改用新地址访问」；
  • 已打开的旧页面无法自救（旧 IP 已失联），必须以桌面端提示的新地址重开——这是本需求的边界。

6.3 桌面悬浮码（贴边呼吸球，FR-75~79）

桌面壳专属的常驻扫码入口：独立置顶透明小窗（手机浏览器不渲染），任何页面都能扫。交互模型一句话——贴边收拢、靠近预览、拖动换边：

  • 形态：收拢态为 64px 呼吸圆点——透明无底盘（不画球体背景与投影，直接悬浮在桌面上），珊瑚粉呼吸环（缩放 .92↔1.08 + 描边加粗 + 明暗，2s 一循环）+ 微信绿 44px 圆芯（30px 取景框内嵌小号 CC 字标）；窗口中心压屏幕边缘线、圆点漏一半在屏内；默认停靠屏幕左侧垂直居中；
  • 预览：指针停留 1.5 秒 → 滑出 136×190「浏览器扫一扫」扫码卡（按吸附边方向滑入）；离开 250ms 收拢。预览卡是纯展示——点击它与点击圆点等效（打开主窗口并收起面板），不提供放大/关闭等按钮；
  • 拖动：按住拖动、松手自动吸附最近边缘（并列优先左）——在哪块屏就吸哪块屏的边，支持扩展屏；拖动位置与所在显示器一并持久化（pet-dock.json 记显示器锚），重启后回到同一块屏的原位；记忆的显示器离线（拔线/休眠）时先落到当前屏、不改记忆，插回后自动归位；启动时先落位再显示，不会先在主屏闪现；顶部吸附受 macOS 限制钳制在菜单栏下沿（该边完整贴边而非半隐，属系统行为）；
  • 服务状态：外圈粉环呼吸 = 运行中，静止常亮 = 已停止——动效本身即状态，不再用灰环/去色重复表达；
  • 提醒：有新文件或新消息时环上弹出绿点（与呼吸环同组、随环一起缩放，按吸附边落在屏幕可见的半侧）；主窗口打开期间不展示并在打开时清零（用户已在软件里，无需提醒）；
  • 开关：唯一关闭入口是 CC设置「悬浮二维码」开关；关闭立即消失，状态本地持久化、重启保持；打开即恢复显示（含此前记忆的停靠位置）。
持久化选型：位置记忆（pet-dock.json）与开关状态（pref-qr-float-enabled）都走 Rust 侧同步写文件——WKWebView 的 localStorage 写入在实测中长期只驻内存不落盘，重启即丢，不能承担"重启后仍保持"类需求。

13安全模型与边界

信任模型 可信局域网使用。控制台接口（启停/日志/清空）与文件接口均无鉴权——请只在可信 Wi-Fi 下使用，不要把端口暴露到公网。

13.1 内置防护

  • 路径穿越双重防护：URL 解码 → 相对路径逐段校验（拒绝空/./../首尾空格/非法字符，支持子目录）→ 与共享目录拼接后 canonicalize 校验前缀越界；上传建目录前对最近存在的祖先做越界预检（防符号链接把目录建到界外）；
  • 浏览器跨源防护：Host 必须是 IP / localhost（不再放行 *.local——同 Wi-Fi 攻击者可自架 mDNS 应答做 DNS 重绑定绕过访问码，二维码本就下发 IP，收紧无损正常路径）；带 Origin 的请求精确匹配放行自身与 WebView（tauri://localhost、http(s)://tauri.localhost；子串匹配可被 tauri.localhost.evil.com 绕过，禁止使用）；无 Origin 的 curl/局域网 App 不受影响；
  • 控制接口仅限本机：/api/control/*（启停/日志/清空）拒绝非回环来源——局域网任意设备可调用的话人人能关停服务、读走全部活动日志；网页端状态走 /api/info，不受影响；旧版安全模式偏好不再生效，服务始终开放局域网。
  • 资源有界：日志单行 400 字符硬截断（防超长 URL 灌内存）并剥 CR/LF（防日志注入）；上传边收边校验声明大小，未知大小上传每 64MB 复查磁盘剩余；Windows 路径长度（MAX_PATH 260，按 UTF-16 计）上传预检；并发闸下载 32 / 上传 16 / WS 64，上传连续 60s 增量 < 16KB 即中止（防慢速滴流占满槽位）；
  • 删除与清理边界：删除符号链接只删链接本身（canonical 目标不删）；Windows 读路径拒绝尾随点/空格/ADS 别名，删除用 canonical 真实相对名做在途/标记保护；启动清理 .ccpart 只认带会话指纹且能对上 meta 首行 id FNV 指纹的命名（<name>.<16hex>.ccpart/.meta），普通 .ccpart 用户文件可见且保留；.ccup 只处理合法令牌/"ok"/空标记，用户自建同名文件不触碰；
  • 隐私与垃圾过滤：系统垃圾文件（.DS_Store/._*/Thumbs.db/desktop.ini）不进列表、上传拒绝——.DS_Store 内含目录内曾出现过的文件名元数据；
  • CSP 纵深防御：WebView 配置最小 Content-Security-Policy（script-src 'self'、object-src 'none' 等），即便出现注入型 XSS 也限制其能力；connect-src 放行 http:/ws:/wss:，img-src/media-src 放行 http: 与 blob:，frame-src 放行 http:（不再 'none'）——移动壳既可能连本机节点也可能连电脑，应用内预览要从局域网地址加载图片/音视频/PDF，只留回环会把发版包整端拦死（v1.2.2 已删除各平台 conf 的重复 CSP，统一由基础配置继承）；html/svg/xml 仍由服务端 inline 白名单禁止同源打开（dev 模式无 CSP，必须用发版包验证）；
  • 系统命令注入防护（Windows）：打开 URL 走 rundll32 FileProtocolHandler、文件走 explorer，不经 cmd shell（cmd 会解释 &|^ 等字符）；
  • XSS 防护：聊天消息先转义再链接化；
  • 资源上限：聊天 200 条（总字符 200 万）/ 昵称 20 字 / 单条消息 200000 字 / 日志 2000 条；
  • 删除确认：所有删除必须经确认框。
